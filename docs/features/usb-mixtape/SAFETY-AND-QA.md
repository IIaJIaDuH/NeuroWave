# USB Mixtape — безопасность носителей, отказоустойчивость и QA

**Статус:** T-001…T-026 покрыты офлайн-тестами USB-03/04/05 на fake-USB и синтетическом аудио, кроме T-019 (playback); CLI USB-06 проверен офлайн на fake-USB, включая отказ без подтверждения и eject только после завершённой задачи. Реальные FAT32/exFAT и железо — USB-08.
**Приоритет:** не потерять пользовательские данные. Подборка может быть неполной; чужая флешка/диск не должен измениться по ошибке.

## 1. Модель угроз

| Угроза | Сила воздействия | Мера |
|---|---|---|
| Приложение выбрало системный раздел вместо USB | Критично | Drive/Block/Filesystem через UDisks2; отклонять HintSystem, internal, некорректные кандидаты |
| Пользователь поменял флешку после preview | Критично | fingerprint/UUID/major-minor/object-path, revalidate перед записью и на границах файлов |
| Симлинк/.. ведёт из MUSIC в домашний каталог | Критично | path containment, O_NOFOLLOW + dirfd / безопасный файловый API, запрет следования symlink |
| USB выдернули во время записи | Высоко | tmp-файл, journal, fail-safe stop, resume только после проверки |
| Перезаписан чужой файл | Критично | no-clobber semantics, резерв имени, явное согласие на update own files |
| FAT/exFAT не поддерживает необычное имя | Средне | ограничение длины, безопасные символы, casefold-collision, optional ASCII |
| Флешка полна или носитель read-only | Высоко | budget с резервом, ENOSPC/EROFS handling, частичный отчёт |
| Злонамеренный USB manifest | Высоко | schema/size limits, UTF-8 validation, external path rejection, no eval |
| Токены/история попали на флешку | Средне | минимальный manifest, redact local roots и секреты |
| Ссылка на URL во внешнем импорте вызывает SSRF | Высоко | сетевые адаптеры вне MVP; после — allowlist/redirection/IP policies |
| Параллельная задача пишет в ту же папку | Высоко | per-volume lock и exclusive job coordination |
| Обнаружение USB выдало сетевой/виртуальный том | Высоко | positive validation; сомнительное устройство не eligible |
| Конвертер ffmpeg читает небезопасные источники | Высоко | локальный approved input, argv без shell, timeout, ограничение внешних протоколов |

## 2. Правила обнаружения и выбора USB

1. Подключение слушаем через UDisks2 ObjectManager, устройство берем по Block/Drive/Filesystem связям; не исходим из красивого имени «USB» и позиции /dev/sdb1.
2. Положительная проверка съёмного USB-устройства, носителя с допустимым fs, read-write mount, free bytes. Не использовать *только* флаг Drive.Removable: у реальных USB SSD он может вести себя иначе; неоднозначный случай требует безопасного отказа/дополнительной проверки и ручного разрешённого UX.
3. Запрет системных дисков/разделов, root/home/swap/дисков со служебными mountpoints; никаких fstab/system чужих носителей. Штатные точки съёмных томов `/media/...` (Mint) и `/run/media/...` (Fedora) разрешены; системными считаются только `/run`, `/run/lock`, `/run/user`.
4. После выбора фиксировать immutable DeviceIdentity с UDisks object path + stable drive identifier (если есть) + filesystem UUID (если есть) + mount path + current device identity. Не полагаться на UUID в одиночку: он может дублироваться или отсутствовать.
5. Проверять, что выбранная папка и mountpoint принадлежат именно тому же файловому устройству, непосредственно перед writer; после размонтирования mountpoint путь может вновь указывать на обычную папку хоста → **fail closed**.
6. Когда данные о файловой системе или идентичности не подтверждены, результат — **device_unverified**, никакой fallback к прямому /media/user/USB.
7. После завершения используем Filesystem.Unmount; PowerOff (если поддерживается подходящим Drive) как отдельное безопасное действие. Отправлять пользователя к системной функции, если аппаратный eject не поддерживается. Никогда не делать raw eject без учёта открытых файлов.

- https://storaged.org/doc/udisks2-api/latest/gdbus-org.freedesktop.UDisks2.Drive.html

## 3. Safe Writer: алгоритм

**Подготовка**

- После user consent заново валидировать DeviceIdentity и mountpoint.
- Проверить root: это выбранная папка внутри подтверждённого тома, ни один компонент не symlink. Никаких absolute paths, .., NUL, control chars, скрытых сегментов, зарезервированных имён, превышения длины.
- Создать exclusive marker/lock в **своём** каталоге на USB и локальный журнал. Игнорировать lock других программ нельзя; stale lock требует аккуратного recovery.
- Проверить свободное место + резерв **10% или 256 MiB, выбирая более строгий практический порог**; резерв конфигурируется, на маленьких флешках предусмотреть обоснованный адаптивный предел. Не считать оценку transcode точной.
- Записать snapshot плана/согласия локально до любых файловых операций.

**Каждый файл**

- Revalidate носитель и корневые descriptor/инварианты, затем открыть source только внутри разрешённой локальной библиотеки без следования symlink наружу.
- Использовать descriptor-relative операции (например, openat + O_NOFOLLOW/O_DIRECTORY/O_EXCL) или эквивалентную проверенную библиотеку. Простого Path.resolve() недостаточно против TOCTOU.
- Имя уникальное, sanitized, portable, collision-free даже при case-insensitive FS. Нумерация и треки не позволяют подменять имя пользователя служебным файлом.
- Создать временный файл **в том же конечном filesystem** с O_CREAT|O_EXCL, правами владельца по возможностям FS; потоковая запись чанками с жёстким ограничением RAM.
- Вычислить hash исходника и destination. После fsync проверять наличие файла, длину, формат, checksum. На нестабильных USB fsync не является универсальной гарантией сохранности после внезапной потери питания.
- Для transcode: decoder/probe проверяет duration, container, channels и успех exit-code; checksum входа **не обязан** совпадать с checksum выходного файла; финальный manifest хранит output hash.
- Финализировать **без перезаписи существующего файла**. Сначала `link` (атомарный no-clobber), иначе `renameat2(RENAME_NOREPLACE)`. Проверка «файла нет» перед `rename` запрещена: она не атомарна. Если ФС или архитектура не дают гарантии no-replace — fail closed (`no_atomic_replace`), запись прекращается без повреждения данных. Тест на ext4 не доказывает поведение FAT32/exFAT: нужен носитель именно с этой ФС.
- До первого `mkdir`, manifest и playlist вызвать `revalidate` **и** `assert_mountpoint`: каталог назначения обязан быть точкой монтирования подтверждённого тома по `/proc/self/mountinfo`. Иначе после размонтирования каталог на диске хоста принял бы запись. Проверка повторяется перед каждым файлом и каждой записью manifest/playlist вместе со сверкой `st_dev/st_ino` открытого каталога с путём монтирования.
- `manifest.json` читать и писать только относительно открытого каталога (`openat` + `O_NOFOLLOW`). Первое создание — no-clobber: параллельно созданный чужой manifest не перезаписывается; дальше заменяется только файл с подтверждённой identity, исчезновение/подмена — отказ.
- `playlist.m3u8` обновлять только при manifest этой же задачи (поле `playlist`); первый экспорт — no-clobber commit, symlink/подмена → отказ; пользовательский файл не удаляется. Атомарного «заменить, если inode тот же» в POSIX нет, поэтому своя запись не заменяется, а версионируется (`playlist-2.m3u8` и далее) тем же no-clobber commit'ом. Гонка на выбранное имя разрешается следующим свободным.
- После успешного финального commit записать журнал атомарно. Никакой команды удалить все старые файлы после ошибочного прогонов.
- Перепроверять доступный объём при каждой крупной записи, ENOSPC превращать в paused/failed без порчи соседних файлов.

**Завершение**

- Сформировать M3U8 из **фактически committed** файлов; playlist не должен указывать на skipped/failed.
- Manifest содержит только собственные относительные имена и контрольные суммы. Писать через tmp+fsync+rename с учётом ограничений FS. Не обещать весь job как одну атомарную транзакцию.
- Закрыть дескрипторы, sync/writeback, завершить процесс конвертации, только потом разрешить safe eject.

## 4. Недоверенный USB: дополнительные защиты

- **USB-документ не источник команд.** Импортированным manifests запрещено формировать произвольные source paths, URL и параметры shell.
- JSON ограничить глубиной, суммарными байтами, числом entries и общей длиной строк; schema_version обязателен, неизвестная версия не мигрируется молча.
- Никаких симлинков в destination tree, которые выходят наружу; в fake filesystem тестировать symlink swap между проверкой и open.
- На FAT32 отсутствуют Unix permission bits и symlink стандартного Linux-формата — защитные проверки всё равно нужны для других FS и fake-tests.
- Проверять дисковую ёмкость через actual filesystem stats + UDisks, не верить только USB metadata и старому плану.
- В USB-папке собственные идентификаторы задач **не заменяют** проверку содержимого и фактических файлов.

## 6. CI-слои

1. **Pure unit (любой Linux runner):** planner, dedup, name sanitizer, provenance policy, state machine, manifest parser.
2. **Integration (tmp sandbox):** fake UDisks2/device, controlled fault injection ENOSPC/EROFS/EIO, malicious symlink/race, kill/resume, no-clobber; без доступа к настоящему /dev/sdX.
3. **Codec integration:** ffmpeg только если установлен; генерировать свои синтетические тестовые тона, проверять output metadata. Никакой защищённой музыки в репозитории/CI.
4. **Manual hardware on Mint:** реальная USB-флешка, writable FAT32 и exFAT, SUSPENDED → Mounted, удаление, проверка магнитолы, playback в фоне, долгий тест. Носитель заранее подготовленный/пустой; не форматировать автоматически.
5. **Security:** fuzz filenames/manifest, path traversal, symlink swap, concurrent writer, download adapter SSRF при его появлении.

## 7. Метрики и гейты

- **Данные:** 0 чужих перезаписанных/удалённых файлов во всех тестах, 0 записей на непроверенные устройства.
- **Байты:** 100% committed файлов имеют подтверждённый output hash/формат, playlist указывает только на проверенные файлы.
- **Ресурсы:** PSS всего дерева, пик и средний CPU, скорость копирования, частота disk writes, фризы UI, фактические underrun при параллельном mpv — зафиксировать и сравнить с PR #9 baseline. Ориентир 200 МБ при базовом воспроизведении **не** означает, что экспорт без ограничений обязан укладываться в 200 МБ; превышение документируется и обосновывается.
- **Стабильность:** cancel, unplug, ENOSPC, relaunch и resume не выводят основной плеер из строя.
- **Юридическая чистота:** пакет не содержит аудио пользователя, токены, чужие binary без аудита, stream-ripping.
- **Опциональность:** без UDisks2, ffmpeg, GUI или сетевых разрешённых источников можно запускать существующий NeuroWave без ошибок импортов.

## 8. Техническая готовность к реальному USB

Перед аппаратным прогоном пользователь должен вручную подтвердить, что выбранный USB предназначен для тестов; **не тестировать на системном диске**. Обязательно иметь резервную копию важных файлов. Даже write-only реализация, если содержит ошибку, способна повредить пользовательские данные — проверять постепенно от sandbox к реальной флешке.

Результат manual smoke — отдельный отчёт с UUID, FS type (без приватного серийного номера), метриками, списком failure cases и сохранёнными контрольными суммами.
