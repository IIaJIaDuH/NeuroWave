# USB Mixtape — продуктовая и функциональная спецификация (v0.1)

**Статус:** проект ТЗ; код ещё не реализован.  
**Цель:** сформировать персональную автономную USB-сборку только из правомерно экспортируемого аудио и проверить запись.  
**Целевая среда:** Linux Mint 22.x (Cinnamon), Python 3.10+, существующее headless-ядро, последующий Qt Widgets UI.  
**Связано:** [ADR-0007](../../decisions/0007-usb-mixtape.md), [ADR-0005](../../decisions/0005-audio-engine.md).

## 1. Цели, пользовательские истории, ограничения

**Пользовательские истории**

- **US-01 (автомобиль):** как владелец USB-магнитолы, выбираю «в дорогу», длительность 4 часа и MP3; получаю заполненную папку MUSIC, совместимую с устройством в пределах выбранного профиля.
- **US-02 (личные предпочтения):** строю подборку на основе лайков/истории и могу исключить исполнителей/треки до записи.
- **US-03 (локальные файлы):** когда провайдеры недоступны, собираю сборку полностью офлайн из собственного каталога.
- **US-04 (частичный результат):** при нехватке разрешённых файлов вижу реальную длительность, причины пропуска и могу продолжить с неполной подборкой.
- **US-05 (безопасность):** вижу точный накопитель и свободное место; случайно выбранный системный диск не может стать местом назначения.
- **US-06 (повторное использование):** при повторном подключении того же накопителя могу дополнить сборник без замены уже существующих пользовательских файлов.
- **US-07 (доступность):** без Qt доступен CLI с preview JSON, включая режим без записи.
- **US-08 (контроль):** могу остановить задачу, возобновить по журналу или очистить временные файлы **только внутри принадлежащей приложению папки**, с подтверждением.

**Неподдерживаемые действия:** скрытая запись, автоматический выбор тома при нескольких устройствах, форматирование, raw-запись, скачивание из стримингового кеша, сохранение лицензированного стриминга в аудиофайл, DRM обход, генерация/апскейл «lossless» из сжатого аудио.

## 2. Основной UX

### 2.1 Обнаружение накопителя

- **FR-001** При обнаружении съёмного USB-тома показать: метку, размер/свободный объём, filesystem, тип подключения, UUID, точку монтирования, доступность записи. Для нераспознанных и системных томов действия записи недоступны.
- **FR-002** При нескольких томах пользователь выбирает нужный; при исчезновении/смене идентичности или перемонтировании весь план и подтверждение инвалидируются.
- **FR-003** Использовать D-Bus UDisks2, а не разбор текстовых сообщений «lsblk» как единственный критерий. Не запрашивать sudo. Если требуются полномочия — показывать системный запрос UDisks2/Polkit или отказ.

### 2.2 Мастер сборки

- **FR-010** Профили: Car USB, Road, Party, Chill, Favorites; шаблоны — данные, не hard-coded логика. Дополнительный ручной выбор треков.
- **FR-011** Настройки: желаемая длительность 1–12 часов; ограничение размера; фильтр исполнителей/жанров; без дублей; последовательность vs shuffle с фиксированным seed; целевой формат Original / MP3 до 320 kbps / FLAC source-only.
- **FR-012** Car USB по умолчанию: только MP3, папка MUSIC, латинские безопасные имена/транслитерация как отдельная опция, M3U с относительными путями, нумерация 001...; никакой гарантии универсальной совместимости.
- **FR-013** Предпросмотр до USB-записи: количество кандидатов, успешных файлов, отсутствие файла, неизвестные права, конфликты названий, примерный размер, разрешённые источники.
- **FR-014** Кандидаты из Yandex/Spotify/SoundCloud могут влиять на **музыкальные рекомендации**, но сам экспорт осуществляется только из отдельно подтверждённого источника автономных файлов. Сопоставление названий не даёт согласия на использование другого файла без preview.
- **FR-015** Пользователь может вручную удалить/переупорядочить песни, заменить неверный match, заблокировать отдельные треки и исполнителей. Система не «лечит музыкальный вкус» без запроса.

### 2.3 Правила подбора

- **FR-020** Детерминированный baseline (без LLM): liked + play count + recency + negative-feedback + user-selected mood + diversity penalty + constraints (duration/size) + seeded shuffle.
- **FR-021** Для каждого кандидата хранить explanation/reason: «лайк», «часто слушаешь», «в жанре», «добавлено вручную»; если метаданных мало — «из локальной библиотеки», не выдумывать настроение.
- **FR-022** Поиск дубликатов в два этапа: normalize(title, artist, duration tolerance), затем hash конкретного файла; версия/ремастер/кавер с другим аудио — отдельные варианты. Не использовать только Track.id, так как provider-qualified ID не эквивалентен файлу.
- **FR-023** Не скачивать чужой трек автоматически, если metadata match неоднозначен: предоставить список альтернатив и ручное подтверждение.
- **FR-024** Не обещать точную длительность при недостатке eligible-аудио: показывать целевое и достижимое время отдельно.

### 2.4 План, копирование, завершение

- **FR-030** До записи требуется **явный user confirmation**, включающий идентичность USB-тома, место назначения, количество файлов, estimated bytes, режим конфликтов.
- **FR-031** Запись только в выбранный каталог (предпочтительно MUSIC/NeuroWave или выбранная новая папка), без удаления чужих файлов. Профиль «обновить сборник» ограничивается manifest-owned файлами после подтверждения.
- **FR-032** Writer выполняет streaming copy с ограниченным буфером, hash на входе/после записи, временным именем на целевом томе, затем rename. При ошибке не помечать файл готовым.
- **FR-033** Поддерживать pause/cancel по файлам, replay из manifest с повторной проверкой совпадения устройства и хешей; после выдёргивания USB — stopped/device_missing, никаких новых файлов.
- **FR-034** Создавать playlist.m3u8 (UTF-8, относительные пути) и итоговый manifest.json в папке NeuroWave только после успешной проверки. Скрываться от неизвестных старых проигрывателей опционально.
- **FR-035** Процесс копирования в UI/CLI: состояния, текущий трек, записанные байты, скорость, оставшееся время как оценка, процент и проверенные файлы.
- **FR-036** После записи — sync/flush, затем безопасное извлечение через UDisks2 при запросе пользователя и проверке, что writer полностью завершён.
- **FR-037** По умолчанию **не переписывать** существующий путь. Повторная запись своего manifest-owned файла требует явного режима обновления + подтверждения.

### 2.5 Форматы и качество

- **FR-040** Оригинал: без перекодирования, если целевое устройство поддерживает формат. MP3: копировать уже пригодный MP3 без потерь качества при совпадении конфигурации; в остальных случаях транскодировать только с разрешением, при наличии ffmpeg/кодека.
- **FR-041** FLAC-only: включать только реальные lossless-оригиналы. Не выводить FLAC из MP3/Opus как «Hi-Fi»; при несовместимости показывать ограничение.
- **FR-042** Нельзя объявлять битрейт 320 kbps повышением качества: он характеризует выходной файл, не исходное аудио.
- **FR-043** Для FAT32 лимит размера одного файла меньше 4 GiB, для имён учитываются правила конкретной файловой системы; long path / Unicode / ошибки кодировок покрываются тестами.
- **FR-044** Метаданные, изображения и атрибуция пишутся только когда источник и права разрешают; возможность записи тегов и конвертации проверяется пробами.

## 3. Таблица пользовательских ошибок

| Ситуация | Поведение |
|---|---|
| Нет USB или нет writable USB | Preview разрешён; кнопка записи отключена |
| Только системный диск | Не предлагать его как целевое USB-устройство |
| Флешка вытащена | Остановить I/O, пометить interrupted, не переключаться на другой том |
| Кончилось место | Прервать/сохранить журнал, не удалять чужие файлы |
| Недостаточно экспортируемых треков | Показать пропуски и частичный результат, подтвердить намерение |
| Нет ffmpeg | Только Original / копирование совместимого формата |
| Один файл повреждён | Пропустить/пометить failed, дать пользователю итоговый отчёт |
| Уже есть такое имя | Предсказуемый суффикс, skip или ручное решение, но не silent overwrite |
| Файл за пределами разрешённого root | Запретить, не пытаться разрешить доступ через symlink |

## 4. Нефункциональные требования

- **NFR-01:** модуль опциональный, **не** меняет AudioBackend, mpv, PlayerService и фоновые правила Spotify/Yandex.
- **NFR-02:** ограниченная RAM независимо от размера файла; никакого чтения много-гигабайтного файла целиком.
- **NFR-03:** writer на worker thread/process, без блокировки главного UI-потока; playback остаётся отзывчивым.
- **NFR-04:** журнал не содержит токенов, DRM/media URLs и приватных ключей. История предпочтений остаётся локальной.
- **NFR-05:** права доступа к внутреннему state/temp под XDG, временные каталоги не world-writable.
- **NFR-06:** тестируемый backend с fake removable volume; не требуется физический USB для unit/CI.
- **NFR-07:** изолированный manifest со схемой и версией; не доверять содержимому manifest с флешки без проверки пути и устройства.
- **NFR-08:** многопользовательские USB-монты и чужие каталоги: принцип least privilege; без sudo, no arbitrary root.
- **NFR-09:** ошибки источников и накопителя классифицированы, диагностируемы и возвращаются в CLI --json.
- **NFR-10:** операции записи opt-in; никакого «вставил — сразу пошла запись» без включённого режима и явного подтверждения.

## 5. Минимальный публичный CLI (реализован в USB-06)

~~~text
neurowave mixtape devices --json
neurowave mixtape plan --profile road --hours 4 --format mp3 \
    --confirm-local-rights --save plan.json --json
neurowave mixtape export --plan plan.json --target <udisks-object-id> --confirm
neurowave mixtape status --job <id> --json
neurowave mixtape cancel --job <id>
neurowave mixtape verify --job <id> --json
neurowave mixtape eject --target <udisks-object-id> --confirm
~~~

Путь к mountpoint не может заменять проверенный object ID. План хранится в
файле 0600 и содержит `plan_id`; export пересобирает план и отказывается при
расхождении. **Нет** флага, обходящего подтверждение/проверку устройства:
`export` требует `--confirm` и план с `--confirm-local-rights`, `eject` —
отдельный `--confirm` и завершённую задачу; `eject --job` дополнительно
проверяет, что задача относится к тому же object path, что и `--target`.

`verify` возвращает `ok=true` только для задачи в статусе `complete`, все
пункты которой `verified` и совпали по sha256/size: `partial`/`failed`/
`cancelled`, а также `failed`/`skipped`-файлы внутри задачи считаются
расхождением (`not_verified:<status>`) с кодом выхода 1.

## 5a. Qt-экран и мост (USB-07)

План и запись живут в одном `mixtape/service.py` (`plan/export/verify`,
коды `library_missing`, `rights_not_confirmed`, `plan_changed`,
`target_not_found`): CLI и GUI вызывают его, а не свои копии шагов. Экран
`ui/mixtape.py` — тонкий слой над Qt-независимым `mixtape/bridge.py`, так
что та же логика работает без PySide6 и проверяется обычными тестами. Мост
отдаёт неизменяемый снимок (`status`, `devices`, `preview`, `progress`,
`summary`, `verification`, `can_*`) и выполняет план/запись/проверку/извлечение
в отдельном потоке; отрисовка идёт по таймеру GUI-потока (NFR-03), окно не
трогает аудио и mpv. До записи видны том, папка, число разрешённых файлов,
оценка байт и причины пропуска; прогресс показывает проценты, файлы, байты,
скорость и оценку остатка (FR-035). Согласие сохраняется: без отметки прав и
подтверждения диалога экспорт не стартует, `eject` доступен только после
завершения worker'а.

## 6. Критерии приёмки MVP

- [ ] На тестовом FAT32/exFAT USB формируется playlist с корректными относительными ссылками и полным совпадением хешей скопированных файлов.
- [ ] Полностью офлайн и без GUI система умеет создать подборку из LocalMusicAdapter; треки стриминговых провайдеров без ExportAsset не проходят в writer.
- [ ] Никакого format/partition/delete внешних файлов; при сценарии с symlink/traversal все выходы за целевой root отклонены.
- [ ] Замена накопителя между plan/confirm/write вызывает отказ. При извлечении посреди записи можно восстановить свою задачу после проверки файлов.
- [ ] Дубликаты не добавляются молча, коллизии имён детерминированны; файл пользователя не перезаписан.
- [ ] При нехватке места и нестабильных источниках результат честный: partial + report, без ложного complete.
- [ ] Playback в параллельной сессии не заикается на тестовом стенде; метрики сохранены.
- [ ] Конвертация не нарушает модель качества и проходит юридическую проверку зависимости ffmpeg.
- [ ] Реальная USB-проверка и CI unit/integration документированы.

## 7. Открытые вопросы

**Перед реализацией:** проверить старую автомагнитолу (FAT32/exFAT, кодировка/длина имён, поддержка M3U); границы объёма; UX выбора папки; правила лицензирования музыки для конкретных сценариев; нужны ли обложки внутри MP3; какие именно разрешённые download-провайдеры доступны с официальным API.

**Приоритет:** сначала безопасный офлайн-MVP, потом сеть, потом AI-подбор. Не наоборот.
