## Контекст

Публичный GitHub-репозиторий до решения не содержал LICENSE, а метаданные пакета объявляли Proprietary. Открытый доступ к исходникам сам по себе **не предоставляет** общую лицензию на их воспроизведение, модификацию и распространение. Для осмысленного публичного релиза выбран явный лицензионный режим.

В Python-процессе NeuroWave ранее использовал GPL-библиотеку mutagen только для чтения тегов локальных MP3/OGG/M4A/FLAC. Это не требуется для других функций mutagen, например редактирования тегов.

## Решение

1. Публиковать собственный код NeuroWave под **MIT**, с текстом [LICENSE](../../LICENSE) и строкой **Copyright (c) 2026 Максим Зозин**.
2. В pyproject.toml: `license = "MIT"`, в metadata authors — `Максим Зозин`. Использовать современный build backend с поддержкой SPDX по PEP 639.
3. Убрать mutagen из `local` extras и из кода. Применять **TinyTag >=2.3,<3** (MIT), с возвратом к метаданным из имени файла, если TinyTag отсутствует или не может прочитать заголовки.
4. Не сохранять mutagen как отдельную «GPL-опцию» в поддерживаемой конфигурации NeuroWave. Сторонние пакеты пользователя не входят в нашу поставку.
5. Не трактовать MIT как лицензию **всех зависимостей**. Обязательства сторонних компонентов сохраняются: LGPL для библиотеки в Python-процессе и Qt, GPL для отдельного mpv, условия действительной сборки FFmpeg/mpv и другие.
6. Бинарный публичный релиз допустим **только** после аудита фактического комплекта: лицензии, NOTICE, исходники/условия доступности, пакеты, поставка mpv, внешние plugin dependencies и воспроизводимость сборки.
7. Уважать авторские права независимых контрибьюторов: MIT в корне применяется к коду, который правообладатель вправе лицензировать. Для внешних существенных вкладов обеспечить разрешение/совместимость прежде, чем утверждать что весь исторический код однозначно принадлежит одному лицу.

## Проверенный факт совместимости TinyTag

Исследование для этого ADR на тестовых MP3, OGG/Vorbis, M4A/AAC и FLAC показало совпадение основных полей title, artist, album и duration. Важный нюанс: **TinyTag возвращает bitrate в кбит/с**, а mutagen возвращал бит/с. Поэтому новую функцию `_read_tags` нельзя механически оставить с `// 1000`.

TinyTag предоставляет отдельные common fields (`tag.title`, `tag.artist`, `tag.album`, `tag.duration`, `tag.bitrate`) и дополнительные записи артистов через `tag.other`. Невалидные/отсутствующие теги должны оставлять работоспособный fallback по имени файла. Регрессионные тесты включены в PR.

## Альтернативы и причины отказа

| Вариант | Оценка |
|---|---|
| **MIT + TinyTag** | **Выбрано.** Разрешительная лицензия на наш код, минимальная зависимость для чтения метаданных |
| GPL-3.0-or-later + mutagen | Допустимая альтернатива, но ограничивает интеграцию нашего кода в закрытые решения; необходимость GPL для чтения тегов не доказана |
| Proprietary | Отклонено. Не соответствует намерению предоставлять пользователям открытый проект по понятной лицензии |
| MIT с необязательным mutagen | Отклонено как штатный вариант поставки: дополнительная ветка лицензирования затрудняет поддержку и проверку готовых пакетов |

## Лицензионные границы

- **NeuroWave source**: MIT (то, что правообладатель вправе лицензировать).
- **mpv**: отдельный GPL-процесс, управляемый через JSON IPC; лицензия mpv обязательна при его распространении вместе с продуктом. Линковка с конкретной сборкой libmpv потребует нового анализа.
- **yandex-music и PySide6**: LGPL-условия по фактическим версиям и модели использования; MIT нашего кода их не отменяет.
- **TinyTag**: MIT, read-only; работа с тегами/качеством проверяется регрессионными тестами.
- **Контент музыкальных провайдеров**: отдельные права и условия, не затрагиваются MIT-лицензией приложения.
