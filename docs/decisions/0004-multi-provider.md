# ADR-0004: Провайдеры музыки — возможности вместо обещаний

**Статус:** принято и частично реализовано. Реестр провайдеров и контракт
возможностей — в коде; гейт перед вторым провайдером закрыт (квалифицированные
ID + маршрутизация), подключены Яндекс Музыка, локальные файлы, SoundCloud и
Spotify в режиме «пульт». Остальные сервисы — по мере подтверждённой поддержки.
**Дата:** 2026-11-16.
**Связано:** [ADR-0002](0002-python-core-prototype.md), [ADR-0003](0003-ui-foundation.md),
[ТЗ §2](../SPEC.md).

## Контекст

Запрос: «добавить возможность подключения других провайдеров — VK Music,
Spotify и других». Ядро до сих пор жёстко создавало `YandexMusicAdapter`
в `cli.Context`, а `PlayerService` ожидал от адаптера ссылку на поток.

Проверка документации сервисов (ноябрь 2026) показала, что «подключить
провайдера» — не одна задача, а четыре разных:

| Сервис | Официальный API | Поток в стороннее приложение | Что реально возможно |
|---|---|---|---|
| Яндекс Музыка | неофициальный (библиотека `yandex-music`) | да, ссылка на поток | всё: каталог, волна, библиотека, mpv |
| SoundCloud | да, нужен ключ (Artist Pro) | да, для `playable` треков | каталог + поток в mpv; обязательна атрибуция, офлайн-кеш запрещён |
| Локальные файлы / MPD | не нужен | да (свои файлы) | каталог + поток; ни DRM, ни подписки |
| Spotify | да (Web API) | **нет**: Web Playback SDK работает в браузере и ссылку не выдаёт | каталог, библиотека, управление устройством Spotify Connect («пульт») |
| Deezer | да | только 30-секундные превью | каталог и библиотека |
| TIDAL | да | только через официальный Player SDK | каталог и метаданные |
| Apple Music | да (MusicKit) | только через MusicKit | каталог и библиотека; нативного Linux-SDK не подтверждено |
| YouTube Music | отдельного API музыки нет | извлечение аудио запрещено политикой | каталог/поиск YouTube, не больше |
| VK Музыка | публичных аудио-методов нет (закрыты с 2016) | нет | только по договорённости с VK; обход не поддерживаем |

Источники: [Spotify Web Playback SDK](https://developer.spotify.com/documentation/web-playback-sdk),
[политика Spotify](https://developer.spotify.com/policy),
[Spotify Apps / Dev Mode](https://developer.spotify.com/documentation/web-api/concepts/apps),
[VK: права доступа](https://dev.vk.com/en/reference/access-rights),
[закрытие VK audio API](https://vk.com/dev/audio_api),
[Deezer API](https://developers.deezer.com/api) и
[FAQ для разработчиков](https://support.deezer.com/hc/en-gb/articles/360011538897-Deezer-FAQs-For-Developers),
[гайд SoundCloud API](https://developers.soundcloud.com/docs/api/guide) и
[условия API](https://developers.soundcloud.com/docs/api/terms-of-use),
[YouTube Data API](https://developers.google.com/youtube/v3/docs) и
[политики разработчика](https://developers.google.com/youtube/terms/developer-policies),
[TIDAL Developer Guidelines](https://developer.tidal.com/documentation/guidelines/guidelines-developer-guidelines),
[Apple MusicKit](https://developer.apple.com/musickit).

Главный вывод: **общего «дай мне URL» контракта не существует.** Если сделать
его единственным требованием к провайдеру, половина сервисов либо не
подключится, либо подключится нарушением условий.

## Решение

1. **Возможности вместо обещаний.** У провайдера есть
   `ProviderInfo.capabilities` (`Capability`): `CATALOG`, `LIBRARY`,
   `PLAYLISTS`, `PERSONAL_RADIO`, `DIRECT_STREAM`, `DELEGATED_PLAYBACK`,
   `LYRICS`. Ядро и UI обязаны спрашивать возможность, а не имя сервиса.
2. **Три режима воспроизведения**, а не один:
   * `DIRECT_STREAM` — ссылка играется нашим `mpv` (Яндекс, SoundCloud, локальные файлы);
   * `DELEGATED_PLAYBACK` — управляем чужим плеером/устройством (Spotify Connect), `mpv` не участвует;
   * «только каталог» — поиск и библиотека без звука в приложении; действие
     «открыть в сервисе» вместо кнопки play.
3. **Реестр провайдеров** (`src/neurowave/providers`): встроенные записи плюс
   сторонние через entry points группы `neurowave.providers`. Ядро не правится
   при добавлении провайдера.
4. **Токен — на провайдера.** `TokenStore(paths, provider=...)`: отдельная
   запись в keyring (`<provider>-oauth`) и отдельный файл `token.<provider>`;
   для Яндекса сохранены исторические имена, чтобы входы не потерялись.
5. **Выбор провайдера на сессию**: флаг `--provider ID` или `settings.provider`,
   по умолчанию `yandex`. `neurowave providers` показывает, что подключено,
   что известно, но не подключено, и почему.
6. **Планируемые провайдеры описаны честно**: `providers/catalog.py` хранит
   VK/Deezer/TIDAL/YouTube Music с причиной, по которой они не подключены. Это не TODO-список, а зафиксированное знание.
7. **Квалифицированные ID.** `Track.key` = `provider:track_id`; сырое `id`
   остаётся для адаптеров. По `key` работают очередь, история, лайки, снимок
   очереди и дисковый кеш, поэтому «123» у Яндекса и «123» у локальных файлов —
   разные треки. Смешанная очередь разрешена.
8. **Поток — у владельца трека.** `ProviderRouter` выбирает адаптер по
   `track.provider` для `stream_url`, `wave_tracks` и `wave_feedback`; адаптер по
   умолчанию обслуживает треки без провайдера (старые записи).
9. **Кеш — по возможностям.** `ProviderInfo.cache_allowed`: у локальных файлов
   `False` (файл уже на диске), у сервисов с запретом хранения — тоже `False`.

## Что сознательно не делаем

* **Не тянем поток из Spotify, TIDAL, Apple Music, Deezer, YouTube Music**
  обходными путями: это нарушает условия и ломается при первом изменении
  клиента. Для Spotify возможен только режим «пульт».
* **Не строим VK-адаптер** на недокументированных интерфейсах: публичного
  музыкального API нет, поддержка требовала бы договорённости с VK.
* **Не притворяемся, что 30-секундное превью — это трек.** Если у провайдера
  нет полного потока, его нет и в интерфейсе.

## Гейт перед вторым провайдером (закрыт)

Гейт был жёстким, потому что до него трек идентифицировался строкой `Track.id`,
а история, кеш и снимок очереди хранили её без имени провайдера. Пункты ниже
выполнены; раздел оставлен как запись решения и критерий пересмотра.

1. Ввести квалифицированные идентификаторы (`provider:track_id`) в `Track`,
   истории, кеше и снимке очереди; миграция SQLite с обратной совместимостью.
2. Маршрутизировать `stream_url`/`wave_feedback` по провайдеру в
   `PlayerService` (сейчас сессия обслуживает ровно один провайдер).
3. Сделать выбор провайдера в UI и смешанные очереди либо явно их запретить.
4. Отключить дисковый кеш для провайдеров, чьи условия это запрещают
   (SoundCloud — запрещено постоянное хранение).

До выполнения этих пунктов подключение второго провайдера давало коллизии ID
(например, «123» у Яндекса и «123» у SoundCloud) — тихую порчу истории
и воспроизведения, поэтому гейт был жёстким.

## Выполнение гейта

1. **Квалифицированные ID.** `Track.provider` и `Track.key` (= `provider:id`),
   `Track.split_key`; `Queue`, история, лайки и снимок очереди работают по
   `key`. SQLite переведён на схему v2 (`history.provider`, `history.track_key`
   с индексом, `likes` с первичным ключом `track_key`); строки схемы v1 при
   открытии помечаются провайдером `yandex` — других провайдеров тогда не было.
2. **Маршрутизация.** `src/neurowave/providers/router.py` — `ProviderRouter` с
   ленивыми адаптерами: `stream_url(track)`, `wave_tracks()`,
   `wave_feedback(kind, track_key)`, `cache_allowed(track)`. `PlayerService`
   получает `router` и берёт ссылку, волну и feedback у владельца трека;
   предзагрузка кеша тоже идёт через роутер и уважает `cache_allowed`.
3. **Выбор провайдера и смешанные очереди.** `--provider ID` / `settings.provider`
   и `neurowave providers`; ограничения видны из возможностей (например, у
   локальных файлов нет `LIBRARY` и `PERSONAL_RADIO`), очередь может содержать
   треки разных провайдеров благодаря `key`.
4. **Кеш по условиям.** `ProviderInfo.cache_allowed`, ключ кеша — `track.key`.

Второй провайдер — **локальные файлы** (`src/neurowave/local`): скан папки
(`local_music_dir`, по умолчанию `~/Music`), теги через `mutagen` (extras
`[local]`) с резервом на имена файлов, защита от выхода за пределы папки,
`lossless` только по расширению. Возможности: `CATALOG`, `DIRECT_STREAM`,
`SHUFFLE_LIBRARY`; `PERSONAL_RADIO` ему не приписывается — «волна» здесь
случайная выборка, и CLI говорит это вслух. Кеш отключён.

Третий провайдер — **SoundCloud** (`src/neurowave/soundcloud`). Подключено ровно
то, что сервис разрешает без обходов:

* возможности `CATALOG`, `DIRECT_STREAM`; ни `LIBRARY`, ни `PLAYLISTS`, ни
  `PERSONAL_RADIO` — их требуют обещать только с пользовательским токеном и
  отдельной проверкой;
* ключ — `AuthKind.API_TOKEN`: `neurowave login --token <client_id или access
  token>`; access token (`2-…`) уходит заголовком `Authorization: OAuth`, а
  client_id — параметром `client_id`;
* в очередь попадают только треки с `access=playable`: 30-секундные превью и
  `blocked` отбрасываются, а `stream_url` перепроверяет доступность перед
  выдачей ссылки;
* атрибуция: исполнитель берётся из `user.username`, страница трека
  сохраняется в `Track.url` и печатается в CLI;
* `cache_allowed=False`: условия API запрещают постоянное хранение, поэтому
  кеш и предзагрузка для SoundCloud выключены полностью;
* сеть живёт в `soundcloud/client.py` на стандартной библиотеке, транспорт
  подменяется, поэтому тесты не ходят в интернет.

Четвёртый провайдер — **Spotify** (`src/neurowave/spotify`) — только «пульт»:

* возможности `CATALOG`, `DELEGATED_PLAYBACK`; `DIRECT_STREAM` нет, поэтому
  `plays_in_mpv=False` и `neurowave play` для него отказывает;
* в адаптере намеренно нет `stream_url`: поток не извлекается ни при каких
  условиях, ссылку Web API не выдаёт. `ProviderRouter` отвечает «не отдаёт
  поток: воспроизведение возможно только в плеере сервиса»;
* команды: `neurowave devices` (список устройств Connect), `neurowave connect
  <id|имя>` (перенос воспроизведения), `neurowave remote play|pause|next|previous
  [запрос] [--uri spotify:track:…]`;
* токен — OAuth access token (`AuthKind.API_TOKEN`, `login --token`),
  проверяется запросом `/me` при входе; Premium нужен для управления и
  распознаётся в `me` по полю `product`;
* `login --token … --refresh-token … --client-id …` включает обновление:
  access token обновляется заранее (по `expires_at`) и по `401`, новый
  refresh token сохраняется в `TokenStore`. Без refresh token истечение даёт
  понятную ошибку с командой повторного входа, а не молчаливый отказ;
* кеша нет (`cache_allowed=False`) — кешировать нечего, поток остаётся в
  Spotify; `403` объясняется требованием Premium, `404` — отсутствием
  активного устройства;
* тесты идут на фейковом транспорте: URL/заголовки/тела PUT/POST, `204` без
  тела, отказы `401/403/404/429/5xx`, парсинг устройств и каталога.

## Последствия

- `PlayerService` получил необязательный `router`: без него работает прежний
  путь с одним адаптером. Провайдер по-прежнему отдаёт `wave_tracks`,
  `stream_url`, `wave_feedback`. Для режима «пульт» понадобится отдельный
  контроллер, который не создаёт `mpv`-поток (следующий шаг).
- CLI: `--provider`, `providers`; `doctor` показывает выбранного провайдера.
- MPRIS и трей работают с любым провайдером, у которого есть `DIRECT_STREAM`,
  без изменений (они видят только `PlayerService`).
- Тесты: реестр, возможности, entry points, изоляция токенов, CLI — всё без
  сети и без реальных аккаунтов.

## Порядок подключения (по убыванию реалистичности)

1. ~~**Локальные файлы / MPD**~~ — подключено (`--provider local`): без
   аккаунта и DRM, проверяет модель данных на реальном втором провайдере.
2. ~~**SoundCloud**~~ — подключено (`--provider soundcloud`): официальный
   поток для `playable`-треков, ключ приложения и отключённый кеш.
3. ~~**Spotify**~~ — подключено (`--provider spotify`): каталог и «пульт»
   Spotify Connect без потока и без кеша.
4. **VK, TIDAL, Deezer, Apple Music, YouTube Music** — только при появлении
   официальной поддержки потоковой передачи сторонним клиентам.

## Критерий пересмотра

- Если сервис открывает официальный способ отдавать поток стороннему плееру —
  добавляем `DIRECT_STREAM` и подключаем.
- Если Spotify закрывает Connect-управление для новых приложений — режим
  «пульт» убирается, остаётся каталог.
- Если появятся коллизии ID (одинаковый `key` у разных треков) — гейт
  считается невыполненным, и провайдер отключается до исправления.
- Если сервис запрещает дисковый кеш — ставим `cache_allowed=False`, а не
  «забываем» про запрет.
