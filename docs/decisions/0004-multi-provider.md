# ADR-0004: Провайдеры музыки — возможности вместо обещаний

**Статус:** принято. Реестр провайдеров и контракт возможностей — в коде;
конкретные сервисы подключаются по мере подтверждённой поддержки.
**Дата:** 2026-11-16.
**Связано:** [ADR-0002](0002-python-core-prototype.md), [ADR-0003](0003-ui-foundation.md),
[ТЗ §2](../SPEC.md).

## Контекст

Запрос: «добавить возможность подключения других провайдеров — VK Music,
Spotify и других». Ядро до сих пор жёстко создавало `YandexMusicAdapter`
в `cli.Context`, а `PlayerService` ожидал от адаптера ссылку на поток.

Проверка документации сервисов (ноябрь 2026) показала, что «подключить
провайдера» — не одна задача, а четыре разных:

| Сервис | Официальный API | Поток в стороннее приложение | Что реально возможно |
|---|---|---|---|
| Яндекс Музыка | неофициальный (библиотека `yandex-music`) | да, ссылка на поток | всё: каталог, волна, библиотека, mpv |
| SoundCloud | да, нужен ключ (Artist Pro) | да, для `playable` треков | каталог + поток в mpv; обязательна атрибуция, офлайн-кеш запрещён |
| Локальные файлы / MPD | не нужен | да (свои файлы) | каталог + поток; ни DRM, ни подписки |
| Spotify | да (Web API) | **нет**: Web Playback SDK работает в браузере и ссылку не выдаёт | каталог, библиотека, управление устройством Spotify Connect («пульт») |
| Deezer | да | только 30-секундные превью | каталог и библиотека |
| TIDAL | да | только через официальный Player SDK | каталог и метаданные |
| Apple Music | да (MusicKit) | только через MusicKit | каталог и библиотека; нативного Linux-SDK не подтверждено |
| YouTube Music | отдельного API музыки нет | извлечение аудио запрещено политикой | каталог/поиск YouTube, не больше |
| VK Музыка | публичных аудио-методов нет (закрыты с 2016) | нет | только по договорённости с VK; обход не поддерживаем |

Источники: [Spotify Web Playback SDK](https://developer.spotify.com/documentation/web-playback-sdk),
[политика Spotify](https://developer.spotify.com/policy),
[Spotify Apps / Dev Mode](https://developer.spotify.com/documentation/web-api/concepts/apps),
[VK: права доступа](https://dev.vk.com/en/reference/access-rights),
[закрытие VK audio API](https://vk.com/dev/audio_api),
[Deezer API](https://developers.deezer.com/api) и
[FAQ для разработчиков](https://support.deezer.com/hc/en-gb/articles/360011538897-Deezer-FAQs-For-Developers),
[гайд SoundCloud API](https://developers.soundcloud.com/docs/api/guide) и
[условия API](https://developers.soundcloud.com/docs/api/terms-of-use),
[YouTube Data API](https://developers.google.com/youtube/v3/docs) и
[политики разработчика](https://developers.google.com/youtube/terms/developer-policies),
[TIDAL Developer Guidelines](https://developer.tidal.com/documentation/guidelines/guidelines-developer-guidelines),
[Apple MusicKit](https://developer.apple.com/musickit).

Главный вывод: **общего «дай мне URL» контракта не существует.** Если сделать
его единственным требованием к провайдеру, половина сервисов либо не
подключится, либо подключится нарушением условий.

## Решение

1. **Возможности вместо обещаний.** У провайдера есть
   `ProviderInfo.capabilities` (`Capability`): `CATALOG`, `LIBRARY`,
   `PLAYLISTS`, `PERSONAL_RADIO`, `DIRECT_STREAM`, `DELEGATED_PLAYBACK`,
   `LYRICS`. Ядро и UI обязаны спрашивать возможность, а не имя сервиса.
2. **Три режима воспроизведения**, а не один:
   * `DIRECT_STREAM` — ссылка играется нашим `mpv` (Яндекс, SoundCloud, локальные файлы);
   * `DELEGATED_PLAYBACK` — управляем чужим плеером/устройством (Spotify Connect), `mpv` не участвует;
   * «только каталог» — поиск и библиотека без звука в приложении; действие
     «открыть в сервисе» вместо кнопки play.
3. **Реестр провайдеров** (`src/neurowave/providers`): встроенные записи плюс
   сторонние через entry points группы `neurowave.providers`. Ядро не правится
   при добавлении провайдера.
4. **Токен — на провайдера.** `TokenStore(paths, provider=...)`: отдельная
   запись в keyring (`<provider>-oauth`) и отдельный файл `token.<provider>`;
   для Яндекса сохранены исторические имена, чтобы входы не потерялись.
5. **Выбор провайдера на сессию**: флаг `--provider ID` или `settings.provider`,
   по умолчанию `yandex`. `neurowave providers` показывает, что подключено,
   что известно, но не подключено, и почему.
6. **Планируемые провайдеры описаны честно**: `providers/catalog.py` хранит
   Spotify/VK/Deezer/TIDAL/YouTube Music/SoundCloud/локальные файлы с причиной,
   по которой они не подключены. Это не TODO-список, а зафиксированное знание.

## Что сознательно не делаем

* **Не тянем поток из Spotify, TIDAL, Apple Music, Deezer, YouTube Music**
  обходными путями: это нарушает условия и ломается при первом изменении
  клиента. Для Spotify возможен только режим «пульт».
* **Не строим VK-адаптер** на недокументированных интерфейсах: публичного
  музыкального API нет, поддержка требовала бы договорённости с VK.
* **Не притворяемся, что 30-секундное превью — это трек.** Если у провайдера
  нет полного потока, его нет и в интерфейсе.

## Обязательный гейт перед вторым провайдером

Сейчас трек идентифицируется строкой `Track.id`, а история, кеш и снимок
очереди хранят её без имени провайдера. Перед подключением второго провайдера
**обязательно**:

1. Ввести квалифицированные идентификаторы (`provider:track_id`) в `Track`,
   истории, кеше и снимке очереди; миграция SQLite с обратной совместимостью.
2. Маршрутизировать `stream_url`/`wave_feedback` по провайдеру в
   `PlayerService` (сейчас сессия обслуживает ровно один провайдер).
3. Сделать выбор провайдера в UI и смешанные очереди либо явно их запретить.
4. Отключить дисковый кеш для провайдеров, чьи условия это запрещают
   (SoundCloud — запрещено постоянное хранение).

До выполнения этих пунктов подключение второго провайдера даст коллизии ID
(например, «123» у Яндекса и «123» у SoundCloud) — это тихая порча истории
и воспроизведения, поэтому гейт жёсткий.

## Последствия

- `PlayerService` не изменился: провайдер по-прежнему отдаёт `wave_tracks`,
  `stream_url`, `wave_feedback`. Для режима «пульт» понадобится отдельный
  контроллер, который не создаёт `mpv`-поток (следующий шаг).
- CLI: `--provider`, `providers`; `doctor` показывает выбранного провайдера.
- MPRIS и трей работают с любым провайдером, у которого есть `DIRECT_STREAM`,
  без изменений (они видят только `PlayerService`).
- Тесты: реестр, возможности, entry points, изоляция токенов, CLI — всё без
  сети и без реальных аккаунтов.

## Порядок подключения (по убыванию реалистичности)

1. **Локальные файлы / MPD** — без аккаунта, без DRM, проверяет модель данных.
2. **SoundCloud** — единственный крупный сервис с официальным потоком;
   требует ключа и отключения кеша.
3. **Spotify** — только каталог + Spotify Connect, если будет доступ к Web API.
4. **VK, TIDAL, Deezer, Apple Music, YouTube Music** — только при появлении
   официальной поддержки потоковой передачи сторонним клиентам.

## Критерий пересмотра

- Если сервис открывает официальный способ отдавать поток стороннему плееру —
  добавляем `DIRECT_STREAM` и подключаем.
- Если Spotify закрывает Connect-управление для новых приложений — режим
  «пульт» убирается, остаётся каталог.
- Если после второго провайдера появятся жалобы на коллизии ID — гейт выше
  считается невыполненным, и провайдер отключается до миграции.
