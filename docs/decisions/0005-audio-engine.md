# ADR-0005 — Audio Engine: separate mpv + JSON IPC + lavfi

- **Статус:** Accepted (принято для следующего этапа; критерии пересмотра остаются в силе)
- **Дата:** 2026-11-16
- **Репозиторий:** `IIaJIaDuH/NeuroWave`
- **Связанное:** ADR-0002, ADR-0003, ADR-0004, PR #9, `docs/SPRINT0-MEASUREMENTS.md`

## Контекст

NeuroWave уже использует отдельный `mpv`-процесс и JSON IPC для headless-воспроизведения. На Linux Mint 22.3 (Ryzen 7 5800X / PipeWire / Bose QC Ultra SBC / HDMI Nvidia) измерены PSS 127,7 МБ Bluetooth и 121,8 МБ HDMI, CPU около 1,8–1,9% одного ядра, 0 зафиксированных underrun в коротких 100-секундных сессиях. Фильтры `equalizer`, `alimiter`, `loudnorm` доступны через `lavfi`. Интерфейс Qt и Sound Lab пока не реализованы.

Перед выбором нужно учитывать: PCM-файл из `--ao=pcm` не подтверждает параллельный живой PCM tap для FFT; физический HDMI-звук не проверен; CloudMus/YaMusic на целевой машине не сравнивались; текущий режим Bluetooth использовал SBC; долгих soak-проверок нет. Публичный репозиторий пока не имеет выбранной открытой лицензии.

## Решение

**Основной аудиодвижок: внешний `mpv` + JSON IPC + `lavfi` внутри процесса mpv.**

1. Сохраняем `AudioBackend`/`PlayerService` и отдельный процесс mpv; Qt UI не получает прямого доступа к сокету.
2. Pure Hi-Fi обходит *пользовательские* DSP фильтры NeuroWave (но не обещает аппаратный bit-perfect при PipeWire/Bluetooth).
3. Enhanced строит безопасный проверяемый фильтр-граф: preamp, параметрический EQ, опциональная нормализация, limiter в конце цепи.
4. DSP применяем через документированные команды mpv (`af set`, `af toggle`, `af-command` там, где фильтры их поддерживают). Проверяем ответы, актуальные свойства и rollback.
5. Пока limiter не прошёл тесты, цифровая громкость >100% не рекламируется как безопасная и блокируется.
6. Выбор BT/HDMI и сообщения о реальном кодеке реализуем отдельно от DSP. Не меняем системную конфигурацию PipeWire без согласия пользователя.
7. FFT — отдельный, отключаемый PCM tap PoC по конкретному потоку NeuroWave; не используем захват общего sink/микрофона. Не превращаем `--ao=pcm` в ложное обещание live capture.
8. `libmpv` допускается только как **альтернативная архитектура** при невыполнении количественных требований после PoC и сравнительного бенчмарка.

## Рассмотренные альтернативы

| Вариант | Преимущества | Риски/недостатки | Решение |
|---|---|---|---|
| External `mpv` + lavfi | Уже работает, измерен, отдельный процесс, устойчивый API управления | PCM tap потребует отдельного решения, изменение графа может давать щелчки | **Принять** |
| Embedded `libmpv` | Меньше границ процессов, прямой API управления | Новый lifecycle, без гарантии PCM callback, нужно сравнение PSS/CPU и реальной лицензии | Отложить |
| PipeWire filter-chain как единственный DSP | Возможен сложный системный граф и внешние плагины | Портируемость, сложное per-app routing, системные настройки | Использовать для PoC/опции, не как обязательный backend |
| Собственный DSP/decode на Python | Полный контроль над формой графа | Дублирование FFmpeg, риск latency/CPU/качества | Отклонить |

## Последствия

- Аудиопроцесс по умолчанию остаётся отдельным от Python GUI; его сбои обрабатываются независимо.
- Публичная поставка отдельного mpv требует соблюдения лицензии mpv и его фактической сборки; приложение не становится автоматически GPL только из-за IPC. Если связать приложение с обычной GPL-сборкой `libmpv`, лицензионные обязательства меняются. Сборка с `-Dgpl=false` может быть LGPL при условии проверки GPL-only частей и связанных библиотек; сам флаг не заменяет аудит. Отдельно проверяется GPL-`mutagen` внутри Python-процесса.
- Целевой бюджет GUI+движок 200 МБ PSS — пока гипотеза; baseline PSS из PR #9 не включает Qt и DSP.
- PCM FFT не входит в обязательный MVP без доказанного частного tap.

## Критерии пересмотра

ADR пересматривается, если:
1. PipeWire tap только конкретного приложения невозможно обеспечить без нарушения воспроизведения или приватности;
2. DSP-граф нельзя безопасно переключать/контролировать, и альтернативные реализации не проходят тесты;
3. Замеры на Mint демонстрируют устойчивые пропуски аудио/неприемлемый рост CPU/PSS, а прототип `libmpv` показывает объективный выигрыш;
4. требуемая будущая функция не реализуема с текущим engine+DSP в разумных пределах.
