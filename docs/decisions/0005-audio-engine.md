# ADR-0005: Аудиодвижок — отдельный mpv + JSON IPC + lavfi

**Статус:** принято 2026-11-16. Фиксирует аудиодвижок для Sprint 2 (Sound Lab)
и Qt-приложения. `libmpv` и PipeWire filter-chain остаются альтернативами с
условиями пересмотра (ниже).
**Дата:** 2026-11-16.
**Связано:** [ADR-0002](0002-python-core-prototype.md),
[ADR-0003](0003-ui-foundation.md), [ADR-0004](0004-multi-provider.md),
[замеры Sprint 0](../SPRINT0-MEASUREMENTS.md), [QA-прогон](../QA-RUN-2026-11-16.md).

## Контекст

Headless-ядро уже играет через отдельный процесс `mpv` и JSON IPC: очередь,
«Моя волна», кеш, MPRIS и трей работают на реальном аккаунте. Перед Sprint 2
нужен ответ, на чём строить необработанный звук (Pure) и DSP (Enhanced).

Что измерено на целевой машине (Mint 22.3, Ryzen 7 5800X, PipeWire 1.0.5,
Bose QC Ultra по SBC, HDMI Nvidia) — [SPRINT0-MEASUREMENTS.md](../SPRINT0-MEASUREMENTS.md):

| Показатель | Значение |
|---|---|
| PSS сессии (Bluetooth / HDMI) | 127.7 / 121.8 МБ, подроцессы mpv — 84 / 79 МБ |
| CPU | ~1.8–1.9 % одного ядра, пики 2.2–2.4 % |
| Underrun демуксера | 0 из 20 и 0 из 19 замеров по 100 с |
| До первого звука (локальный файл) | BT 367 мс, HDMI 205 мс |
| Задержка | квант mpv 60 мс, узел вывода 2.7 мс |
| Для сравнения: Chromium на том же аудио | 458 МБ PSS, CPU 3.4 % |

Доступность DSP проверена фактически: мост `lavfi` в mpv даёт `equalizer`,
`alimiter`, `loudnorm`, `dynaudnorm`, `adeclip`; `--ao=pcm` отдаёт
декодированный PCM; `libpipewire-module-filter-chain.so` и `libmpv.so.2` в
системе есть.

Чего **нет** и что нельзя выдавать за сделанное:

* CloudMus и YaMusic на стенде не запускались и не сравнивались (их нет в
  apt/flatpak/snap). Решение по этому сравнению — ниже.
* `--ao=pcm` доказывает, что PCM можно *выгрузить*, но не даёт
  подтверждённого параллельного live-tap для спектроанализатора.
* Физическое звучание HDMI на подключённом дисплее/ресивере не подтверждено
  (sink был `SUSPENDED`, воспроизведение шло).
* Bluetooth работал на SBC; AAC/LDAC не включались и не измерялись.
* Долгих soak-проверок нет: замеры по 100 с.
* Публичный репозиторий пока **без выбранной лицензии**.

## Решение

**Основной аудиодвижок: внешний `mpv` + JSON IPC + граф `lavfi` внутри
процесса mpv.**

1. `AudioBackend`/`PlayerService` сохраняются. mpv остаётся отдельным
   процессом; Qt UI не получает прямого доступа к сокету — только через
   диспетчер команд.
2. **Pure Hi-Fi** обходит *наши* фильтры (EQ, нормализация, компрессия,
   лимитер) и не обещает bit-perfect: PipeWire ресемплирует, Bluetooth SBC
   сжимает с потерями.
3. **Enhanced** строится как проверяемый граф: `preamp → PEQ →
   (опциональная нормализация) → limiter в конце цепи`.
4. DSP применяется документированными командами mpv (`af set`, `af toggle`,
   `af-command` там, где фильтр это поддерживает). Каждый ответ проверяется,
   фактическое состояние подтверждается чтением свойств, при отказе —
   rollback на последний подтверждённый профиль или Pure.
5. Цифровая громкость **> 100 % не применяется**. Это не осторожность, а
   измеренный факт: `mpv --volume` действует **после** `af`, а его кривая
   кубическая, поэтому 130 % — это +6.8 дБ уже после лимитера (на стенде:
   8475 клипованных отсчётов, inter-sample пик +4.1 dBFS при потолке
   −3 dBFS). Безопасный путь для будущего boost — усиление **внутри** графа
   перед лимитером с потолком не выше −3 dBFS: там 0 клипов и true peak
   −0.75 dBFS. Значение из конфигурации сохраняется, применяется 100 %,
   пользователь получает предупреждение.
6. Выбор BT/HDMI и показ реального кодека — отдельная задача (свой
   идентификатор устройства, не `Settings.audio_backend`). Системные
   настройки PipeWire/WirePlumber без согласия пользователя не меняются.
7. FFT — отдельный отключаемый PoC с персональным tap **только потока
   NeuroWave**; захват общего sink или микрофона не маскируется под
   «спектр плеера».
8. `libmpv` допустим только как альтернативная архитектура при невыполнении
   количественных требований после PoC и сравнительного бенчмарка.

### Судьба сравнения с CloudMus и YaMusic

Сравнение **осознанно отложено до этапа beta** и не блокирует аудиодвижок:

* обе программы на целевой машине отсутствуют, установка требует выбора
  конкретных проектов и внешних зависимостей — это отдельная задача с
  неопределённым объёмом;
* вопрос, ради которого сравнение затевалось (на чём строить звук и UI),
  закрыт измерениями против браузера и проверкой DSP-возможностей mpv;
* полевое сравнение сохраняет ценность как проверка UX и качества звука, но
  должно идти после рабочего GUI, иначе сравнивать нечего.

Статус фиксируется в [ROADMAP](../ROADMAP.md): пункт остаётся открытым с
пометкой «отложено до beta», а в PR-10 (beta hardening) появляется
обязательство либо выполнить сравнение, либо зафиксировать отказ с причинами.

## Рассмотренные альтернативы

| Вариант | Преимущества | Риски и недостатки | Решение |
|---|---|---|---|
| Внешний `mpv` + `lavfi` | Уже работает и измерен; отдельный процесс; стабильный IPC; сбой движка не роняет UI | Live-tap PCM требует отдельного решения; смена графа может щёлкать | **Принять** |
| Встроенный `libmpv` | Нет границы процессов, прямой API | Новый жизненный цикл; отсутствие гарантированного PCM-callback; при обычной GPL-сборке меняются лицензионные обязательства; нужен бенчмарк против текущих цифр | Отложить до доказанной необходимости |
| PipeWire `filter-chain` как единственный DSP | Системный граф, внешние плагины, один обработчик на все приложения | Глобальный слой делает профиль непредсказуемым; сложное per-app routing; зависимость от конфигурации системы | Только PoC и опция, не обязательный backend |
| Собственный DSP/декодер на Python | Полный контроль над формой графа | Дублирование libavfilter, latency, CPU, риск качества | Отклонить |

## Последствия

* Аудиопроцесс по умолчанию отделён от Python/UI: его сбой обрабатывается
  независимо, звук не ждёт сети и интерфейса.
* Поставка отдельного mpv требует соблюдения его лицензии и лицензий
  библиотек сборки. Вызов по IPC сам по себе не делает наш код GPL, но
  **связывание с обычной GPL-сборкой `libmpv` меняет обязательства**.
  Флаг `-Dgpl=false` не является переключателем лицензии: требуется аудит
  фактических GPL-only файлов и связанных библиотек.
* ~~`mutagen` (GPL-2.0-or-later)~~ **устранён**: теги локальных файлов читает
  MIT-`tinytag` ([ADR-0006](0006-license.md)), GPL-модулей внутри Python-процесса
  больше нет. Отдельный mpv остаётся GPL-процессом, что не заразно для нашего
  кода.
* Бюджет 200 МБ PSS для GUI + движок — гипотеза: baseline 122–128 МБ не
  включает Qt и DSP. Цифры после появления UI публикуются отдельно, и
  приоритет отдаётся стабильному звуку, а не цифре любой ценой.
* Спектроанализатор не входит в обязательный MVP: без пройденного gate
  (§6.4 плана) он не выпускается.

## Критерии пересмотра

ADR пересматривается, если выполнено хотя бы одно условие:

1. Не удаётся получить PCM **именно потока NeuroWave** в реальном времени без
   захвата звука других приложений и без разрыва воспроизведения.
2. Граф DSP нельзя переключать без слышимых щелчков/разрывов, и
   альтернативная конфигурация `lavfi` не помогает.
3. На целевой машине появляются устойчивые пропуски, рост CPU/PSS или
   нестабильность, а прототип `libmpv` показывает измеримый выигрыш.
4. Требуется обработка, нереализуемая в libavfilter/PipeWire без неприемлемых
   компромиссов.

## Обязательные проверки после принятия

- [x] P0: ограничение громкости без лимитера и проверка ошибок `af` по IPC —
      PR-02. Подтверждено на живом mpv 0.42: `volume 130` → mpv применяет 100,
      битый граф `af` даёт `error running command` и прежний граф не теряется,
      `loadfile` возвращает `playlist_entry_id` для отсева устаревших `end-file`.
- [x] Enhanced-тракт: применение профиля, сверка с фактическим состоянием
      mpv, откат при отказе, Pure одним переключателем — PR-04. Измерения
      усиления и inter-sample пиков — `packaging/dsp-safety.py`.
- [x] PoC tap только потока NeuroWave при параллельно играющем приложении —
      PR-06: изоляция −86…−92 дБ, добавленная задержка 5 мс. Схема —
      отдельный null-sink для mpv + loopback в системный выход, запись с
      monitor своего sink. Обязательным для MVP спектр не становится:
      реализация FFT остаётся PR-09 и может быть отложена.
- [ ] Звучание на Mint: Bluetooth и **физически** HDMI — PR-05.
- [ ] PSS/CPU после появления GUI и DSP, 6-часовой soak — PR-10.
- [ ] Сравнение CloudMus/YaMusic: выполнено либо отказ зафиксирован — PR-10.
- [ ] Выбор лицензии проекта и ревью `mutagen`/Qt/mpv перед сборкой — PR-10.
