# ADR-0003: Основа интерфейса — Qt Widgets на PySide6, ядро в том же процессе

**Статус:** принято для P0 (Sprint 3), пересматривается по результатам замера PSS
на Mint и перед P1-визуализацией.
**Дата:** 2026-11-16.
**Связано:** [ADR-0002](0002-python-core-prototype.md), [ТЗ §2–4](../SPEC.md),
[SMOKE-SPRINT1](../SMOKE-SPRINT1.md).

## Контекст

ADR-0002 зафиксировал headless-ядро на Python и назвал контракты
`MusicAdapter` / `PlayerService` / `AudioBackend` единственной точкой, к которой
подключается интерфейс. Открытым остался выбор UI-основы и способ подключения.

Что известно из ТЗ и кода:

- целевая платформа — Linux Mint, приоритетные маршруты — Bluetooth и HDMI;
- ориентир памяти — **до 200 МБ на всё** (ядро + mpv + UI), это главный
  продуктовый аргумент против браузера;
- P0 не требует анимаций, спектроанализатора и «вау»-эффектов: нужны список
  треков, поиск, очередь, транспорт, громкость, выбор устройства, настройки;
- «продвинутый футуристичный UI» и спектроанализатор — это **P1**;
- звук уже живёт в отдельном процессе `mpv`; UI в аудиопоток не входит;
- ядро проверяется 67 headless-тестами, и эту проверяемость нельзя потерять.

Чего измерить не удалось: в облачной среде, где готовился этот ADR, нет
системных библиотек Qt и нет прав на их установку — `PySide6` импортируется
только при наличии `libxkbcommon.so.0`, запуск `QApplication` невозможен.
Поэтому **PSS Widgets против QML остаётся неизмеренным**; числа ниже — из ТЗ и
из фактического размера пакета, а не из профилирования. Решение принято в
сторону варианта с большим запасом по памяти и с явным условием пересмотра.

## Рассмотренные варианты

1. **Qt Widgets + PySide6, ядро в том же процессе** (выбран).
2. **QML / Qt Quick + PySide6**, весь интерфейс декларативный.
3. **Qt C++ (Widgets или QML) + ядро Python отдельным процессом по IPC.**

| Критерий | Widgets + PySide6 | QML + PySide6 | C++ + IPC |
|---|---|---|---|
| Память (главный риск) | лучший запас: QWidget-отрисовка без scene graph | +QML-движок и scene graph, обычно дороже | лучший в перспективе, хуже в срок |
| P0-экраны (списки, настройки, клавиатура) | нативно и предсказуемо | плотные списки требуют ручной работы | нативно, но долго |
| P1-визуализация, 60 fps | QPainter/OpenGL-виджет — рабочий, но ручной | лучший инструмент (шейдеры, `MultiEffect`) | лучший |
| Стоимость входа | один язык, тот же venv | плюс QML и его отладка | вторая реализация контракта, протокол, отладка через границу |
| Зависимости на Mint | системные Qt-библиотеки (`libxkbcommon`, `libgl`, `libfontconfig`, `libdbus`) | то же + EGL/OpenGL-стек | Qt-сборка + Python-рантайм |
| Обратимость | виджеты → QML: переписать экраны (не ядро) | | |

Порядок цифр: `PySide6-Essentials 6.12.0` занимает на диске 246 МБ (Qt — 194 МБ),
ядро `src/neurowave` — 384 КБ. То есть вес тащит Qt, а не наш код, и выбор
между Widgets и QML на размер установки почти не влияет — он влияет на
потребление памяти в рантайме, которое как раз и нужно измерить.

## Решение

1. **UI — PySide6, Qt Widgets, Python 3.10+ в том же venv.** Никакого C++ и
   никакого второго процесса на этом этапе.
2. **Ядро в том же процессе**, доступ только через существующий контракт
   `PlayerService`. UI не импортирует `yandex.*` и не работает со `SQLite`/кешем
   напрямую.
3. **Блокирующие вызовы ядра — только в рабочем потоке** (`QThreadPool` /
   `QRunnable`), результат — сигналом в UI-поток. Правило: ни один слот
   интерфейса не делает сетевой запрос, ни один кадр UI не ждёт сеть.
4. **Мост `PlayerBridge(QObject)`**: слоты `play_wave`, `play_pause`, `next`,
   `previous`, `set_volume`, `seek`; сигналы `track_changed`,
   `quality_changed`, `state_changed`, `overlay_changed`, `cache_stats`.
   Ядро о Qt не знает: `src/neurowave` продолжает импортироваться без PySide6.
5. **Никаких анимаций в P0.** Одна тёмная тема на QSS, без покадровой анимации
   и без визуализатора. Это осознанно отложено до P1.
6. **Визуализатор и «футуристичный» слой P1** — отдельное решение после замеров:
   либо `QQuickWidget`-остров (QML только для визуализации), либо QPainter/OpenGL
   виджет. Основное окно при этом остаётся Widgets.
7. **CLI не теряется.** `neurowave` работает как сейчас; PySide6 — extras
   `[ui]`, без него CLI и тесты остаются работоспособными.

## Почему не QML целиком

- **Память — главный риск проекта, и он не измерен.** QML тянет QML-движок и
  scene graph поверх того же Qt; пока нет замеров на Mint, правильнее выбрать
  сторону с запасом, а не с лучшими анимациями.
- **P0 не требует того, за что платят QML.** Анимации, эффекты и спектр — P1.
  Платить памятью на P0 за возможности P1 — плохой обмен.
- **Визуализатор можно взять точечно.** `QQuickWidget` позволяет добавить QML
  ровно туда, где он нужен, без переписывания окна; это дешевле, чем строить
  весь P0 на QML «на будущее».
- **У QML выше порог по системным зависимостям.** В этой среде `QtWidgets`
  падает уже на `libxkbcommon`; QML дополнительно требует EGL/OpenGL-стек,
  которого нет на headless-машинах. Для Mint это решаемо, но проверять надо
  раньше, а не после написания интерфейса.

## Почему не C++ и не IPC сейчас

- Вторая реализация контракта, версионирование протокола, отладка через границу
  процессов — цена, которую платят до того, как UI доказал ценность.
- ADR-0002 уже предусматривает перенос ядра в C++ при провале бюджета памяти:
  тогда контракт естественно станет IPC, а Python-ядро — референсом поведения
  (тесты остаются).

## Критерий пересмотра

Решение пересматривается, если выполняется любое из условий:

1. На Mint PSS всего дерева (`neurowave` + `mpv`) при открытом окне и
   воспроизведении **> 200 МБ**, либо PSS окна UI **> 80 МБ**. Действия по
   порядку: урезать тему/списки и кеш иконок → вынести UI в C++/Widgets с
   ядром по IPC → перенос ядра в C++.
2. В P1 визуализатор на QPainter не держит 30 fps на целевом железе — тогда
   `QQuickWidget`-остров, а не переписывание окна.
3. PySide6 окажется непригоден на Mint 21/22 (несовместимость Qt6 с системным
   стеком) — тогда C++/Qt6 с ядром по IPC.

Замеры: [SMOKE-SPRINT1](../SMOKE-SPRINT1.md) для ядра,
`packaging/smoke-measure.sh` — для дерева процессов, `/proc/<pid>/smaps_rollup` —
для PSS отдельного окна.

## Последствия

- Новая зависимость `PySide6-Essentials` (246 МБ на диске, extras `[ui]`);
  системные пакеты на Mint: `libxkbcommon0`, `libxkbcommon-x11-0`, `libgl1`,
  `libegl1`, `libfontconfig1`, `libdbus-1-3` и `libxcb-*` для X11-платформы.
- Появляется слой `ui/` (окно, модели списков, мост) — ядро и его тесты не
  меняются; добавляется тест-инвариант «`src/neurowave` не импортирует PySide6».
- Потоки: один worker-пул для вызовов ядра; состояние плеера читается только в
  UI-потоке через сигналы, чтобы не смешивать модель состояний с виджетами.
- MPRIS и трей (следующий шаг) делаются поверх того же моста, без изменений
  ядра и без Qt-специфики в `PlayerService`.
- Отложенная цена: если P1 потребует «настоящего» QML-интерфейса, экраны
  придётся переписать. Ядро, мост и тесты при этом сохраняются.

## Открытые вопросы

- Точный бюджет PSS для окна (80 МБ — гипотеза, не измерение).
- Нужен ли GPU-контекст для P1-визуализации на iGPU целевой машины.
- Формат показа качества источника в P0: строка «aac 320» или бейдж с
  отдельным цветом для lossless (косметика, решается в макете).
