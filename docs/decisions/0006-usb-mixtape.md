# ADR-0006: USB Mixtape — автономный экспорт в отдельном модуле

**Статус:** Proposed (к ревью; не означает реализации)  
**Дата:** 2026-11-16  
**Основание:** пользовательская идея USB Mixtape; [ADR-0005](0005-audio-engine.md), [ADR-0004](0004-multi-provider.md).

## Контекст

NeuroWave уже имеет музыкальное ядро, локальную библиотеку, историю, лайки и несколько провайдеров. Требуется собрать персональную подборку и записать её на USB для автономного воспроизведения (в том числе автомагнитолами). При этом большинство потоковых сервисов даёт **право воспроизведения, а не право экспортировать файл**.

USB-операции рискованны: неверный mountpoint, перенос пути через symlink, замена носителя на лету, повреждение FAT/exFAT, пропажа питания и недостаток места. Эти риски не должны угрожать существующим файлам пользователя.

## Решение

1. Разместить фичу в независимом пакете **neurowave.mixtape** с публичным сервисом **MixtapeService**. У ядра музыки только чтение истории и метаданных; никаких побочных эффектов в mpv или провайдерах.
2. Разделить трековую идентичность **Track.key** и файл, разрешённый к экспорту: только **ExportAsset** с проверенным правом и источником байтов может попасть в writer.
3. Источники добавляются отдельными **ExportSource**-адаптерами с явной политикой; **DIRECT_STREAM** и **cache_allowed** *не* дают экспортного права. В первой версии — локальные файлы. Сетевые загрузки — только отдельными opt-in адаптерами после подтверждения API и лицензий.
4. Пользователь всегда видит **dry-run план**, реальный выбранный съёмный том и точный список файлов. Запись начинается **только после подтверждения**. Никакого автоматического форматирования/удаления.
5. USB определяется через UDisks2/проверенный mountpoint; проверяются свойства Block, Drive, Filesystem, UUID/устройство, read-only, свободный объём. Запрет прямого raw-доступа к /dev/ без явной отдельной ADR.
6. Запись только в специально выбранную папку на томе, с безопасной нормализацией имён и контролем symlink/path traversal. Временные файлы создаются **на целевом томе**, затем проверяются и атомарно переименовываются по одному; при извлечении носителя задача останавливается без каскадного удаления.
7. Writer поддерживает resume по manifest с повторной проверкой источника, назначения и checksum. Конфликты названий решаются предсказуемо; существующие чужие файлы не перезаписываются молча.
8. Профили **Car USB**, **Party**, **Chill**, **Favorites** реализуются детерминированно; optional AI может предлагать план, но не получает полномочий на файловые операции.
9. GUI — лишь клиент headless API; отдельный worker выполняет операции в фоне UI, но **без фоновой задачи вне запущенного приложения**. Сервис не блокирует playback.
10. Учитывать совместимость FAT32/exFAT, потребность в ffmpeg только для опциональной конвертации. Никаких новых GPL-обязательств без аудита.

## Альтернативы

| Вариант | Почему не берём |
|---|---|
| Просто скопировать кеш mpv/Yandex | Кеш предназначен для воспроизведения и не доказывает право экспорта |
| Сразу автоматическая загрузка всех треков по стриминговым ссылкам | Нарушает границы лицензий/сервисов и ломается при изменении API |
| Писать прямо на /dev/sdX и форматировать | Ненужный риск утраты данных |
| Добавить методы записи в PlayerService | Смешивает воспроизведение и USB I/O; повышает риск сбоев музыки |
| Сразу LLM-агент с правами на файлы | Избыточно; трудно тестировать и слишком широкие полномочия |
| Готовить весь сборник в RAM | Не соответствует низкому потреблению ресурсов |

## Неизменяемые условия

- **Никаких DRM bypass, записей потокового аудио в файл, подстановки защищённых кешей или скрытой выгрузки стриминга.**
- **Никаких операций с USB без подтверждения конкретного устройства и назначения.**
- **Никаких команд форматирования, изменения разделов, произвольного unlink на носителе.**
- При недостатке разрешённых песен система показывает частичную подборку и объясняет пропуски. Не выдаёт вымышленную «готовую 4-часовую флешку».
- Безопасное завершение и извлечение только после остановки writer и успешной синхронизации.

## Последствия и обязательные PoC

- Простой offline-MVP полезен уже без AI и облачных интеграций.
- Сначала доказать UDisks2 device identity, mount validation, lock against concurrent jobs, запись/обрыв/восстановление на тестовом USB.
- Затем доказать пригодность формата для целевой автомагнитолы и корректность метаданных.
- Сетевые права и загрузки — отдельный gate: для каждого источника доказательство разрешённой загрузки + запрет обхода.
- Перед Merge реализации: unit/integration, реальный физический USB smoke, лицензии, оценка PSS/CPU/USB I/O.
