# Риски и ограничения NeuroWave

| Риск | Как снизить |
|---|---|
| Неофициальный API меняется | Изоляция адаптера; capability probes; тесты и fallback |
| Не каждый формат/качество доступен | Проверять подписку, регион и разрешённые методы; не обещать Lossless |
| Правила сервиса или DRM | Не обходить защиту; документировать ограничения; иметь возможность отключить функцию |
| Лицензии стороннего кода | Не копировать исходники до проверки совместимости MIT/GPL/LGPL/Qt/кодеков |
| **Нет выбранной лицензии проекта** | Решено: MIT ([ADR-0006](decisions/0006-license.md)); `LICENSE` в репозитории и в wheel/sdist |
| **`mutagen` (GPL-2.0-or-later) внутри процесса** | Устранён: теги читает `tinytag` (MIT), `mutagen` удалён из зависимостей и из `src/` (тест `test_no_gpl_mutagen_left_in_project`) |
| **mpv/libmpv и лицензия** | Вызов отдельного mpv по IPC не делает наш код GPL; связывание с GPL-сборкой `libmpv` меняет обязательства; `-Dgpl=false` не отменяет аудит GPL-only файлов и зависимостей |
| **Qt (PySide6) LGPL-3** | Динамическая линковка, уведомления и возможность замены библиотеки; проверить содержимое поставки |
| Аудио-клиппинг при усилении | Громкость >100 % заблокирована: измерено, что `mpv --volume` применяется после `af` и кубически, поэтому 130 % = +6.8 дБ мимо лимитера. Будущий boost — только усиление внутри графа перед лимитером (потолок ≤ −3 dBFS, inter-sample пик −0.75 dBFS) |
| Inter-sample пики выше потолка | Потолок −1 dBFS даёт true peak +1.25 dBFS на транзиентах; для boost нужен запас −3…−3.5 dBFS; проверяется `packaging/dsp-safety.py` |
| Пользовательский профиль с опасными значениями | Профиль собирается только через `AudioProfile` (диапазоны, конечность, дубли частот); при чтении из настроек каждый проверяется заново, битые отбрасываются, встроенные не редактируются |
| Несохранённый профиль потеряется | Sound Lab применяет профиль сразу, но предупреждает, что сохранение отдельное; сохранённые профили переживают перезапуск и проверяются при загрузке |
| Ложное «Enhanced включён» | Проверять ответ `af` и фактическое свойство; при отказе — rollback и сообщение, а не статус успеха |
| Некорректное число в IPC вешает mpv | На живом mpv 0.42 `set_property volume NaN` не отвечает вообще; все числовые параметры валидируются (конечность, тип, диапазон) до отправки |
| Щелчки при смене графа DSP | PoC `af-command`, короткий безопасный спад gain, применение на границе трека, если разрыв подтверждён |
| mpv принимает несуществующий id выхода | На 0.42 `audio-device` с неверным id не даёт ошибки и звук идёт «в никуда»; id проверяется по `audio-device-list` до переключения, при отказе — возврат прежнего выхода |
| `auto` скрывает реальный маршрут | Системный sink показывается рядом с `auto` (`auto → QuietComfort Ultra`), иначе пользователь не понимает, куда играет |
| Bluetooth-профиль HFP снижает качество | Определение активного профиля/кодека (сейчас SBC, `a2dp-sink`) и подсказка пользователю; не обещать LDAC/AAC без проверки |
| PCM tap захватит чужие приложения | PoC (PR-06): mpv играет в свой null-sink, запись с его monitor — чужой звук подавлен на 86–92 дБ, добавленная задержка 5 мс. Общий monitor sink и микрофон не используются; системные настройки не меняются |
| Tap добавит задержку и сломает звук | Loopback в системный выход измерен: единицы миллисекунд; спектр — отключаемая функция, её сбой не останавливает воспроизведение |
| HDMI «работает» без проверки | Подтверждать физическое звучание на подключённом дисплее/ресивере, а не ненулевой `audio-device` |
| GUI блокирует звук или сеть | Все мутации через один диспетчер (команды не выполняются в GUI-потоке), позиция читается фоновым потоком, сетевые старты не ждут интерфейс |
| Сокеты mpv копятся в /tmp | При SIGKILL mpv не удаляет `neurowave-mpv-<pid>.sock`: при старте удаляются сокеты мёртвых pid, чужие живые не трогаются |
| Окно не закрывается по SIGTERM/SIGINT | Qt-цикл не отдаёт управление Python: добавлено «сердцебиение» таймером и обработчики сигналов, есть тест с реальным SIGTERM |
| ИИ потребляет VRAM и RAM | Отдельный запускаемый по требованию процесс, timeout и budget |
| Приватные ключи в публичном репо | keyring, .gitignore, ревью, секрет-сканирование |
| Галлюцинации ИИ-диджея | Строгие схемы действий, проверки существования треков, ограничения и согласование |
| Плохой звук в браузере вызван ОС | A/B-тест одного источника с одинаковыми gain/кодеком/BT-профилем |
| Сравнение с CloudMus/YaMusic не выполнено | Выполнено: [замеры и ограничения](COMPARISON-CLOUDMUS-YAMUSIC.md). Стриминг Яндекса у конкурентов не проверен — нужен интерактивный вход |
