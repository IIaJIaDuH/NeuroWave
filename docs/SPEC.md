# NeuroWave — Техническое задание (рабочая редакция)

**Дата:** 15.11.2026 · **Статус:** проектирование, не реализовано.

## 1. Цель
Нативный Linux-плеер для собственной учётной записи Яндекс Музыки без постоянного открытого браузера. Отличный звук и устойчивое воспроизведение важнее ИИ. Визуальный стиль — футуристичный; производительность — сбалансированная.

## 2. Зафиксированные требования
- Linux (первый дистрибутив Linux Mint), Bluetooth и HDMI.
- Пользователь испытывает недостаток громкости, баса, детализации и объёма.
- Два независимых аудиорежима: **Pure Hi-Fi** (DSP bypass) и **Enhanced** (EQ, preamp, compressor/limiter, bass shelf). Защита от клиппинга обязательна; целевое качество исходного потока нельзя «улучшить» эффектами.
- «Моя волна», лайки, плейлисты, поиск, очередь, тексты, подкасты, синхронизация — если поддерживаются реальным доступным API.
- Авторизация: безопасный вход через браузер при доступности подходящего flow; ручной токен как резервный способ. Нельзя собирать пароль в приложении.
- Временный ограниченный кеш, не постоянная загрузка защищённого контента.
- Футуристичный UI, спектроанализатор на реальных PCM-данных, мини-плеер, трей, уведомления, MPRIS и клавиши мультимедиа.
- Опциональный ИИ: анализ вкусов, рекомендации, объяснения, управление очередью, голосовой ввод; отдельная экспериментальная генерация собственной музыки.
- ИИ не блокирует воспроизведение и не загружается без необходимости.

## 3. Приоритеты
**P0 (MVP):** авторизация; получение библиотеки и «Моей волны»; play/pause/seek/next; поиск; очередь; лайки; выбор аудиоустройства; стабильная обработка сетевых ошибок; 2 аудиорежима с лимитером; минимальные настройки и логирование без секретов.

**P1:** плейлисты, тексты, подкасты, Ynison/синхронизация, расширенный DSP, спектроанализатор, мини-плеер, управление из трея, продвинутый футуристичный UI.

**P2:** ИИ-диджей, голос, персональная статистика, отдельная творческая музыкальная студия. Очередность пересматривается после MVP.

## 4. Нефункциональные цели (требуют измерения)
- Базовый проигрыватель работает без LLM, микрофона и GPU-инференса.
- Звук не зависит от responsiveness интерфейса и сети при наличии достаточного буфера.
- Управление плеером отзывчиво; память и CPU проверяются на одинаковых сценариях относительно браузера и прототипов.
- Целевой baseline памяти **до 200 МБ** в режиме без ИИ — *ориентир, не измеренный результат*, допускает пересмотр по результатам испытаний.
- Контроль кеша по лимиту и сроку хранения; первоначально 2 ГБ.
- Подключение/отключение Bluetooth и HDMI не приводит к аварийному завершению.
- Секреты хранятся в системном keyring; отключаемая локальная история предпочтений.

## 5. Проверки приёмки
- Успешная авторизация и воспроизведение доступного трека, восстановление сессии.
- Библиотека, «Моя волна», поиск, лайки и очередь по реальному аккаунту.
- Переключение устройств и их исчезновение обрабатываются без зависания.
- A/B тест браузера и нашего клиента на одинаковом источнике с согласованным уровнем громкости; DSP выключен.
- Enhanced предотвращает цифровой клиппинг, не создаёт резких всплесков при переключении пресетов.
- ИИ выключен: музыка работает, следов модельных процессов/вызовов нет.
- Логи не содержат секретов. Сбой API не роняет UI.

## 6. Незакрытые вопросы
1. Есть ли активный Яндекс Плюс и какой регион аккаунта? Один аккаунт или несколько?
2. Модели Bluetooth- и HDMI-устройств; PipeWire либо PulseAudio?
3. Нужна ли регулируемая громкость выше 100% с лимитером?
4. ИИ через существующий OpenAI-compatible сервер (FreeToken/vLLM) или выделенную модель?
5. Голос — push-to-talk (предлагается) или wake word?
6. Генерация музыки локально на RTX 5060 Ti 16 GB или внешним сервисом?
7. Лимит кеша 2 ГБ или больше?

## 7. Ограничения
Неофициальное API может измениться, а функции сервиса могут требовать подписки или быть недоступны. Не предусматривать обход DRM, подписок или ограничений. До публичного использования заимствованного кода — лицензионный аудит.
