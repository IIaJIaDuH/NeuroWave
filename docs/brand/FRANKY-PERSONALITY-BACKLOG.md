# DJ Franky Personality — музыкальный характер и реактивные реплики

**Статус:** IDEA / BACKLOG / NOT IMPLEMENTED.  
**Дата:** 2026-11-17.  
**Приоритет:** после стабилизации плеера, UI и API-провайдеров. **Никакой реализации в текущем спринте.**  
**Связано:** [бренд](README.md), [канон персонажа](FRANKY-V1-CANON.md), [план внедрения](DELIVERY.md), [ADR-0004](../decisions/0004-multi-provider.md).

## 1. Задумка

DJ Franky — опциональный персонаж с узнаваемым саркастичным характером и собственными **условными** музыкальными симпатиями. Он может коротко и метко комментировать **выбор пользователя**, необычные переходы между жанрами, повторы, новые открытия, лайки и любимые треки. Комментарии — развлечение, не объективная оценка музыки.

**Пример:** после Rammstein пользователь включает Ольгу Бузову. Franky театрально снимает наушники: «Ты реально включил Бузову после Rammstein? Всё, я увольняюсь нахер!» 😁

**Главное ограничение:** Франки **никогда** не отменяет выбранный трек, не меняет очередь, громкость/DSP и не запускает скачивание/USB-экспорт из-за своих «вкусов». Комментарии можно отключить полностью.

## 2. Слои функциональности — без обязательной нейросети

### Phase A — события + сценарные реплики (MVP, без LLM)

- Подписка только на **существующие** доменные события: track_started, user_selected_track, repeat/skip/like/queue changes, playback_paused; точные имена сверить с реальным API перед кодом.
- Детерминированный rules engine выбирает **готовую реплику** на основании фактического контекста.
- Короткий случайный выбор варианта из разрешённого набора с seed, но с cooldown, чтобы персонаж не повторялся и не становился болтливым.
- Не требовать жанровых метаданных, если провайдер их не отдаёт: непроверенные жанры не угадывать из одного названия. Реакцию «после Rammstein → Бузова» включать только при однозначном матче artist/title или явном пользовательском preset.
- UI получает DTO `FrankyReaction`: text, emotion, optional animation_id, priority, expiry; никаких «выполнить действие плеера».

### Phase B — локальный профиль вкусов пользователя

- Учитывать согласованные пользователем сигналы: лайк, количество прослушиваний, часто повторяемые треки, пропуски, историю смены исполнителей.
- Разделять **предпочтения пользователя** и **выдуманный характер маскота**; он может «любить металл», но не должен объявлять вкусы человека ошибкой вне режима юмора.
- Хранить минимум локальных агрегатов с возможностью **сбросить профиль**; не отправлять историю в сеть по умолчанию.
- Характер и частота реплик — локальные настройки с обратимой миграцией, без новых обязательных полей у Track и без изменения ядра.

### Phase C — необязательная локальная LLM

- Короткий prompt со строгой ролью персонажа и **минимальным** контекстом (исполнитель, трек, тип события, 1–2 предыдущих трека и агрегированные предпочтения).
- Запуск только на opt-in, в отдельном процессе/worker, с ограничением времени, токенов и очереди; при отказе — шаблонная реплика или тишина.
- Результат валидировать как **короткий текст**, без tool calling, команд оболочки или полномочий изменять плейлист/устройство/файлы.
- Не передавать токены, stream URLs, личные каталоги или историю целиком.
- Cloud API — только отдельное решение о приватности и согласии пользователя, не входит в эту задумку.

### Phase D — выразительные реакции и TTS (опционально)

- Использовать утверждённый [визуальный канон DJ Franky v1](FRANKY-V1-CANON.md): ухмылка, недоумение, закатывание глаз, снятие наушников.
- Локальная озвучка (TTS) только с отдельным включением; по умолчанию **выключена**. Не перекрикивать музыку, не менять mpv volume без согласия. Возможен текстовый bubble без голосовых эффектов.
- Учитывать reduced motion, Do Not Disturb, quiet mode, fullscreen, pause/minimized.

## 3. Настройки персонажа

| Параметр | Возможные значения | Значение по умолчанию (предложение) |
|---|---|---|
| `enabled` | off/on | **off** до явного включения |
| `persona` | friendly / sarcastic / wild | sarcastic |
| `profanity` | off/on | off |
| `frequency` | off / rarely / sometimes / often | rarely |
| `cooldown_seconds` | configurable, нижняя граница | ≥180 с |
| `tts_enabled` | off/on | **off** |
| `llm_enabled` | off/on | **off** |
| `user_taste_learning` | off/on + clear | off до согласия |
| `reduced_motion` | respect OS/user preference | on, если системный reduced motion |

Все значения — для будущего проектирования, **не существующие настройки и не обещание сроков**.

## 4. Примеры реплик — творческие наброски, не реальные события приложения

| Триггер | Реплика | Эмоция |
|---|---|---|
| Rammstein → Бузова | «Брат, ты реально включил Бузову? Я увольняюсь нахер!» | disgusted / headphones-off |
| Снова любимый металл | «О, вот теперь разговор пошёл. Проверим, выдержат ли колонки!» | approving |
| Десятый повтор | «На восьмом повторе я всё понял. На десятом уже начал волноваться.» | sarcastic |
| Резкий переход жанра | «Мы что, телепортировались между музыкальными вселенными?» | confused |
| Плейлист в дорогу | «Так, ремни пристегнули. Музыкальный двигатель завёл.» | excited |
| Тишина / без трека | «Я тут, если что. Просто не буду лезть без приглашения.» | idle |

**Не оскорблять человека по-настоящему.** Ярость Франки — гротеск и дружеская шутка над музыкальным контрастом, не травля, не унижение конкретного слушателя. В интерфейсе юмор opt-in, при выключенном мате — заранее утверждённые альтернативы.

## 5. Архитектурные границы (проект)

```text
PlayerService / UI event snapshots (read-only)
                   |
         ReactionEventAdapter
                   |
          FrankyRulesEngine
             |          |
        user taste   static persona
        local data   lines & moods
             \          /
          Cooldown / Dedup
                   |
     FrankyReaction DTO (text/emotion)
                   |
      Optional UI bubble / animation
                   |
        Optional LLM / TTS adapter
```

- Музыка, mpv IPC, DSP и навигация не ждут ответа Franky.
- Реакции обрабатываются с bounded event queue; старые треки/события отбрасываются по generation id.
- Класс реакции не содержит команды и не имеет прав на mutation/FS/network.
- Никаких обязательных LLM, Qt, TTS или GPU imports в headless ядре.
- Никаких отдельных сетевых запросов к Яндексу ради реплики: адаптер и так является внешним риском.
- При выключенном Franky нет worker/timer/listener, способных заметно расходовать CPU/RAM.

## 6. Критерии будущей приёмки

- [ ] Включается и полностью выключается пользователем, тишина по умолчанию.
- [ ] На 100 смен треков не спамит: cooldown/dedup работают, предыдущие треки не «залипают».
- [ ] При выключенном/сломавшемся персонаже музыка без задержек продолжает воспроизводиться.
- [ ] Редактируемые наборы реплик, разные варианты мата и дружелюбности, без инъекции в shell.
- [ ] Локальный вкус сбрасывается, при отключении learning не собирается новая история ради функции.
- [ ] Быстрая смена треков не выдаёт реплику от предыдущего `track_generation`.
- [ ] Опциональные TTS/LLM не мешают mpv, имеют timeout, bounded queues и privacy gate.
- [ ] Unit-тесты rules engine, cooldown, muted/off, ambiguous metadata, ошибки, id collisions.
- [ ] QA на реальном Linux Mint GUI + аудио отдельно от Qt offscreen.

## 7. Когда вернуться

**Только после:** закрытия P0 по отказоустойчивости Yandex, рабочего daily-driver GUI и прохождения основных beta-gates. Не начинать новый код, ADR или зависимости только ради этой идеи. Это **осознанно отложенная** творческая задумка.

**Короткая формула:** «У Франки есть своё мнение. Но пульт — у пользователя».
