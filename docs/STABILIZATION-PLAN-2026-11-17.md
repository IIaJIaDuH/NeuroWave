# NeuroWave — Stabilization First (17 ноября 2026)

**Статус:** рабочая стратегия на бета-стабилизацию. **Цель:** превратить уже созданный функциональный прототип в плеер ежедневного пользования, не увеличивая системные риски новыми фичами.

## 0. Отправная точка — проверена по файлам main

- **Реализовано в коде:** Python 3.10+, отдельный mpv JSON IPC, PlayerService/Queue, квалифицированные Track.key, SQLite и локальная библиотека, Yandex adapter, SoundCloud, Spotify remote, MPRIS, трей, Qt Widgets GUI (`src/neurowave/ui/app.py`), ViewModel и Sound Lab, Pure/Enhanced DSP, пользовательские профили, выбор аудиовыхода, PoC индивидуального PCM-tap.
- **Не реализовано:** FFT-экран, AI DJ, USB Mixtape runtime (ТЗ и ADR-0007 уже в main), студия генерации, новые streaming providers, полноценный музыкальный GUI с поиском/библиотекой/плейлистами и мини-плеером.
- **Проверено с оговорками:** 6-часовой headless `mpv --ao=null` soak — 2690 автопереходов, стабильные fd/threads; вывод о 6-часовой стабильности **памяти** ограничен свопингом, физический HDMI на слух на целевом стенде не проверен. CloudMus/YaMusic сравнивали без входа в сервис.
- **Технический долг:** `src/neurowave/cli.py` — **1336 строк** (~47,5 тыс. символов на 17.11), неофициальная `yandex-music` может измениться, README и архитектурные документы ранее были устаревшими.
- **Лицензия:** MIT проекта принято; бинарная упаковка зависит от аудита сторонних лицензий и фактического набора компонент.

## 1. Feature freeze

До прохождения P0 не начинать писать runtime следующих функций:

- USB Mixtape (документация остается; не удалять), ИИ-диджей, текстовый агент, музыка на GPU, новые провайдеры, FFT, анимации и новую архитектуру аудиодвижка.
- Исключения — **исправление регрессии/ошибки безопасности** и минимальная доработка функционального GUI, без которой пользователь не может пользоваться плеером.
- Не заводить новый ADR вместо исправления явного бага или документирования результата теста. Не наращивать документацию без теста/практической задачи.

## 2. Три приоритетных потока работ

| Приоритет | Поток | Результат | Измеримый критерий |
|---|---|---|---|
| **P0** | Yandex API resilience | адаптер либо корректно работает, либо выдаёт контролируемую ошибку, local-only живёт | контрактные тесты на обезличенных ответах + негативные тесты auth/429/5xx/schema; стабильность потока других провайдеров |
| **P0** | Daily-driver GUI | пользователь реально слушает музыку в Qt, а не только смотрит в окно | 30–60 минут интерактивного теста с настоящим звуком, поиск/волна/seek/volume/output/DSP/network; протокол |
| **P0** | Документы + review gates | README/ROADMAP/implementation отражают текущее main | CI проверяет локальные ссылки и регрессионные ложные заявления; PR проверяется по чеклисту |
| **P1** | CLI decomposition | простое сопровождение cli.py | один API контракт сохранён, эквивалентные --help/JSON/exit codes, все unit+integration зелёные |
| **P1** | Hardware + memory | измеримые ресурсные характеристики | GUI+mpv с реальным выходом; memory+swap/SwapPss, fd/threads/CPU, без PSS-иллюзий |
| **P1** | Release hygiene | безопасная раздача beta | проверены notices/состав wheel/sdist и реальные библиотечные лицензии, секреты не включены |
| **P2** | UX polish | плейер приятен на каждый день | корректные статусы, сообщения и клавиатурная навигация; без новых серверных интеграций |

**Правило:** P1 не блокирует исправление найденных P0 багов. P2 не запускаем до закрытия P0.

## 3. Путь к beta

### Gate A — интерфейс не мешает звуку

- [ ] На Mint с настоящим аудиовыходом: старт приложения, 30–60 минут музыки, пауза/следующий/предыдущий/seek, смена Pure/Enhanced, safe volume, выбор выхода, возврат из потери сети.
- [ ] Не блокируется Qt event loop при медленной/неработающей сети, проседании IPC, смене устройства, чтении метаданных.
- [ ] Громкость >100% по-прежнему фактически ограничена без verified boost, переключение DSP выполняется с подтверждением/откатом.
- [ ] Зафиксированы фактические PSS/CPU/latency и устройство/кодек, не «мы поставили флаг HDMI».

### Gate B — неофициальный провайдер отказывает предсказуемо

- [ ] Сохранённый контракт адаптера не протекает в PlayerService/UI; внутри provider-specific код, наружу domain Track/StreamInfo и классифицированные исключения.
- [ ] Деградация: при 401/403/429/timeout/5xx/неизвестной схеме нет краша GUI, зацикленного retry и утечки токенов.
- [ ] История/локальный каталог и локальное воспроизведение работают при отказе Яндекса.
- [ ] Контрактные фикстуры обезличены, фейковые, без токенов или копий защищённого аудио. Периодический реальный smoke — на машине разработчика, не в публичном CI.

### Gate C — можно сопровождать

- [ ] CLI не монолит с жёстко связанными импортами; обратная совместимость CLI для всех существующих команд/кодов ошибок/JSON.
- [ ] Нет новых circular import, скрытой инициализации сети/Qt при импорте, загрузки LLM/GPU в core.
- [ ] Каждый PR показывает diff, тесты и доказанный результат (не «LLM сказал, что работает»).
- [ ] README/ROADMAP/BETA-CHECKLIST синхронизированы, ссылки в документации не сломаны.

### Gate D — можно раздавать

- [ ] LICENSE MIT и правообладатель; проверено исходное происхождение сторонних вкладов.
- [ ] Соответствующие LGPL/GPL/Apache/MIT notice и требования для реально включённых пакетов, особенно mpv/FFmpeg/PySide6 и транзитивных колёс.
- [ ] Чистая сборка wheel/sdist, отсутствие секретов/локальных трасс/бинарных тестовых файлов, smoke в изолированном окружении.
- [ ] Открытые пробелы (физический HDMI, AAC/LDAC, FFT, package formats) перечислены в release notes и **не выдаются за протестированные**.

## 4. Правила релиза и команды проверки

```bash
python -m compileall -q src tests
python -m pytest -q -m "not integration" --ignore=tests/test_ui_qt.py
QT_QPA_PLATFORM=offscreen python -m pytest -q tests/test_ui_qt.py
python -m pytest -q -m integration
python -m build
git diff --check
```

- Модули PySide6, mpv, extras устанавливать согласно [README](../README.md); CI в GitHub Actions запускать в штатных матрицах, не считать skip тестом.
- Для одного PR — цель и фиксированный scope. Сначала тест, затем код и ручная проверка. Объяснения к ошибкам не заменяют реальные проверки.
- `main` не коммитить напрямую: отдельная ветка и PR, дождаться CI, ревью и только затем merge.

## 5. Границы ответственности здесь / на локальном стенде

**Можно из GitHub:** синхронизация документации, статические CI-проверки, спецификация минимальных тестов/контрактов, code review, отдельные безопасные PR.

**Нужен агент с доступом к Mint/учётной записи/аудио:** реальный Qt smoke, сеть Яндекса с приватным токеном, внешние аппаратные кодеки, мониторинг swap/SwapPss во время долгого теста и фактическая сборка AppImage. Не пересылать токен в GitHub или сообщения агенту — держать локально в keyring.
